# Крафт, добыча и использование предметов (`content/crafting.json`)

Все небоевые использования предметов из `game/1/plugin/*.dat` в одном декларативном файле для нового движка.
Источник правды — PHP-плагины (номера строк после `iconv -f cp1251 -t utf-8`), обзор — `docs/mechanics-progression.md` §3.3, §4.4, §5.
Числа (сложности, количества, кости, `<` или `<=`, занятость, поломки, опыт) перенесены как в PHP. Исключение — явные ошибки:
в данных записано задуманное поведение, а каждое отличие перечислено в разделе «Исправления».

Файл состоит из пяти разделов:

| Раздел | Что | Кол-во |
|---|---|---|
| `recipes` | инструменты крафта: использование открывает меню рецептов (или сразу делает единственный рецепт) | 12 инструментов, 64 рецепта |
| `gathering` | добыча с ресурсного узла или в месте: кирка, кирка мастера, топоры, удочка | 4 |
| `nodes` | ресурсные узлы в локациях: рудная жила, деревья | 2 |
| `consumables` | еда и питьё: все `i.f.*` из `content/items` (кроме пустой бутылки) и противоядие | 50 |
| `special` | использования со своей логикой (не таблица) | 19 |

## Общие соглашения

**`S`** — значение навыка игрока (`skills[n]`, 0..5). Ключи навыков — из `f_speakskillup.dat`: `bow` плотник/лучник,
`stone` ювелир, `food` повар, `currier` кожевник/друид, `weaver` ткач, `lumb` лесоруб, `mine` рудокоп, `fish` рыбак,
`smith` кузнец, `alchemy` алхимик, `healing` лекарь.

**Занятость `busy`** — секунды, на которые ставится `char[6] = now + busy`. Пока `now <= char[6]`, любое `use` отвечает
«Вы должны отдохнуть N сек» (`g.php:185-198`). Призрак не может использовать предметы вовсе (`g.php:188`).
Использовать можно только предмет из своего рюкзака (`f_useitem.dat:29`). Занятость ставится, как только пройдены
проверки навыка/места, то есть и при провале броска.

**Объект шанса `chance`** (одна схема везде):

```
{"die": [a, b], "perLevel": k, "plus": p, "minusDifficulty": true|false, "op": "<" | "<=" | ">="}
успех, если rand(a, b) OP  k*S + p  (− difficulty рецепта, если minusDifficulty)
```

`rand(a, b)` включает обе границы (PHP). Отсутствующий `perLevel` = 0, отсутствующий `plus` = 0, отсутствующий
`minusDifficulty` = false. Пример: `{"die":[1,100],"plus":30,"op":"<"}` — 29%.

**Опыт `exp`** — что передаётся в `addexp()` (общий опыт, навыки от действия не растут, §3 документа). `null` — опыта нет.

| `kind` | Поля | Значение |
|---|---|---|
| `fixed` | `value` | ровно `value` |
| `randUpTo` | `max` | `rand(0, max)`; 0 опыта ничего не делает |
| `randRange` | `min`, `max` | `rand(min, max)` |
| `chance` | `chance` (объект шанса), `then` (вложенный `exp`) | с вероятностью `chance` начисляется `then`, иначе ничего |

Опыт начисляется только при успехе, если не сказано иное.

**Именной предмет `named: true`** — результат получает ID `<make>_<логин без "u.">_` (`f_lookitem.dat:68`). В именные
предметы можно инкрустировать самоцветы.

**Шаблоны в строках** `special`: `{target}` — ID цели (`?to=`), `{gem}` — ID используемого самоцвета, `{k}` — параметр `?k=`,
`{name}` — имя предмета, `{player}` — имя игрока, `{L}` — новый уровень заточки. Ключ `"i.h.p.*"` в `takes`/`needHave`
значит «любой предмет с этим префиксом, одна стопка одного вида» (см. стрелы).

Ключ раздела, оканчивающийся на `.` (`i.w.t.`, `i.w.k.`, `i.i.`, `i.bc.`), — префикс: подходит любой ID, который с него начинается.

`source` в каждой записи — PHP-файл, откуда взяты данные. `messages` — тексты журнала из PHP (для совместимости экранов),
необязательны для логики.

## `recipes` — крафт по рецептам

Ключ — ID инструмента. Поля инструмента:

| Поле | Тип | Смысл |
|---|---|---|
| `about` | str | что это, по-русски |
| `source` | str | PHP-плагин |
| `skill` | str \| null | навык для шанса |
| `needSkill` | bool | навык должен быть > 0, иначе отказ без занятости |
| `refuseIfChanceNotPositive` | bool | для табличного крафта: если `perLevel*S + plus − difficulty <= 0` — «навык слишком низок», ничего не тратится и занятость не ставится. В меню показывается шанс `max(0, …)` (`tsret`) |
| `menu` | bool | `true` — без выбора (`?to=` пусто или неизвестен) показать меню «название (N ресурса, шанс: X%)» по порядку `recipes`; `false` — единственный рецепт выполняется сразу |
| `busy` | int | занятость на попытку, сек |
| `needHere` | [id] | объекты, которые должны быть в локации (`i.s.nakov` наковальня, `i.s.tkach` ткацкий станок) |
| `needHave` | [id] | что должно быть в рюкзаке кроме инструмента до попытки; если оно расходуется, это указано в `takes` / `takesOnSuccess` рецепта |
| `toolConsumed` | `always` \| `success` \| `never` | инструмент тратится: при каждой попытке (до броска) / только при успехе / никогда |
| `toolBreakPercent` | int | шанс поломки инструмента за попытку, `rand(1,100) <= N` (здесь везде 0) |
| `messages` | obj | тексты журнала: `success`, `fail` (`{name}` = название изделия), `lowSkill`, `noFixture`, `missingHave` |
| `recipes` | [рецепт] | в порядке меню PHP |

Поля рецепта:

| Поле | Тип | Смысл |
|---|---|---|
| `key` | int | номер рецепта в PHP (`?to=<key>`), для совместимости ссылок |
| `make` | id | результат |
| `name` | str | название в меню и журнале |
| `count` | int | сколько штук выдаётся при успехе |
| `difficulty` | int | сложность (вычитается из шанса, если `chance.minusDifficulty`) |
| `takes` | {id: n} | тратится **до броска** (теряется и при провале). Если чего-то не хватает — сообщение «У вас недостаточно …» и выход, ничего не тратится (`f_additem.dat:54-66`) |
| `takesOnSuccess` | {id: n} | тратится только при успехе; наличие проверяется до попытки |
| `chance` | объект шанса | см. выше; у табличного крафта `rand(0,100) < 20*S − difficulty` |
| `failGives` | {id: n} | что выдаётся при провале (ступка возвращает пустую бутылку) |
| `named` | bool | результат именной `<make>_<логин>_` |
| `exp` | exp \| null | опыт при успехе |

Порядок попытки: проверки (`needHere`, навык/шанс, `needHave`) → занятость → списать `takes` (и инструмент при `always`) →
бросок → успех: выдать `make`×`count`, списать `takesOnSuccess` (и инструмент при `success`), опыт; провал: выдать `failGives`.

Инструменты:

| Инструмент | Навык | Занят | Место / нужно | Инструмент | Рецептов | Опыт |
|---|---|---|---|---|---|---|
| `i.set.molot` молот | smith | 15 | `i.s.nakov` | не тратится | 15, руда `i.ruda` | `fixed round(d/10)` |
| `i.set.bow` тетива | bow | 15 | — | тратится всегда | 7 луков, ветки `i.log` | `fixed round(d/10)` |
| `i.set.plotn` набор плотника | bow | 10 | — | не тратится | 9, ветки | `fixed round(d/10)` |
| `i.set.prjal` прялка | weaver | 15 | `i.s.tkach` | не тратится | 4, нить `i.sh` | `fixed round(d/10)` |
| `i.set.currier` кожевника | currier | **0** | нужна `i.acid` (1 тратится) | не тратится | 5, шкуры | `randUpTo floor(d/10)` |
| `i.set.koptilka` коптилка | food | 15 | нужна `i.log` (1 тратится) | не тратится | 7 рыб | `randUpTo floor(d/10)` |
| `i.set.stupka` ступка алхимика | alchemy | 15 | нужна `i.f.b.water` (1 тратится); провал → `i.f.b.empty` | не тратится | 12 | `randUpTo floor(d/10)` |
| `i.set.stupka.h` ступка трав | alchemy | 6 | трава тратится всегда, пустая бутылка — при успехе | не тратится | 1 → `i.f.b.heal.great`, `rand(1,100) < 20S−5` | `randUpTo 2` |
| `i.set.stupka.m` ступка корней | alchemy | 6 | корень всегда, бутылка при успехе | не тратится | 1 → `i.f.b.mana.great` | `randUpTo 2` (исправлено) |
| `i.set.arrow` / `i.set.bolt` | bow | 6 | 5 перьев `i.h.p.*` одного вида всегда, 1 ветка при успехе | не тратится | 1 → 5 `i.arrow` / `i.bolt`, `rand(1,100) < 20S` | нет |
| `i.set.leska` леска | bow | 10 | 1 ветка всегда | тратится при успехе | 1 → `i.fishman`, `rand(0,100) < 20S` | нет |

Именные изделия: молот, тетива, плотник, прялка, кожевник. Опыт `fixed round(d/10)` — PHP `round` (половина вверх:
сложность 5 → 1, 85 → 9); если `round(d/10) == 0`, опыта нет. `randUpTo floor(d/10)`: PHP делает `rand(0, d/10)`, дробная граница
отбрасывается (`rand(0, 6.5)` = `rand(0, 6)`), и только если `round(d/10) != 0`.

Перья для стрел: PHP берёт **последнюю** стопку `i.h.p.*` в рюкзаке (жадная регулярка, `i.set.arrow.dat:4,12`) и требует в ней ≥ 5.

## `gathering` — добыча

Ключ — ID инструмента или префикс (`i.w.t.` — любой топор).

| Поле | Тип | Смысл |
|---|---|---|
| `about`, `source` | str | описание, PHP-файл |
| `skill`, `needSkill` | | навык; при 0 — отказ без занятости |
| `busy` | int | занятость на попытку |
| `requiresTarget` | bool | нужен параметр `?to=` (любой). Топор без цели надевается как оружие (`plugin/i.w.dat:7-8`) |
| `node` | id \| null | узел, который должен быть в локации (см. `nodes`); его запас тратится на успехе |
| `locations` | [loc] \| null | где можно (удочка: 60 локаций `$loc_water1`, точное совпадение) |
| `chance` | объект шанса \| null | шанс успеха (у удочки вместо него `table`) |
| `gives` | {id: n} | что даёт успех |
| `table` | obj | только удочка: `die`, `op`, `rows` [{`mult`, `give`, `count`, `text`}]. `rnd = rand(die)`, первая строка, где `rnd < S*mult`, даёт предмет; ни одна — провал |
| `stat` | int | индекс `st[]`, который растёт на успехе (§6: 4 рыба, 5 ветки, 6 руда) |
| `exp` | exp | опыт на успехе |
| `toolBreakPercent` | int | поломка инструмента за попытку: `rand(1,100) <= N`, при любом исходе |
| `extra.gems` | obj | кирки: после успешной добычи, если локация `x<X>x<Y>` с `Y >= minY` или в `where.locations`, выбирается 1 камень из `pick` равновероятно и находится с шансом `chance` (`rand(0,100) < 5`, у кирки мастера `< 15`); `stat` 9 |
| `extra.golem` | obj | кирки: после успешной добычи в `locations` с шансом `rand(0,100) < 1` появляется NPC `n.c.gol.<rand(99,9999)>` из шаблона `n.c.gol` (`content/raw/npc/n.c.gol`), с репликой `message` |
| `messages` | obj | `success`, `fail`, `empty` (узел пуст), `lowSkill`, `noNode`, `noWater`, `broken` |

Итого: кирка — `rand(1,100) < 10S` (49% при 5), занят 4; кирка мастера — `< 10S+10`, занят 3; топор — `rand(1,100) < 10S`,
опыт `rand(1,3)` с шансом 49%; удочка — `rand(0,199)` по таблице, опыт 1 с шансом 9%, поломка 5%.

## `nodes` — ресурсные узлы

| Поле | Смысл |
|---|---|
| `fields` | разбор строки объекта локации `имя|stock|0|regrow|max|regrow_at` |
| `stockField`, `stockMaxField`, `regrowField`, `regrowAtField` | индексы полей в этой строке (1, 4, 3, 5) |
| `regrowSeconds` | задержка восстановления у всех узлов в контенте (300) |
| `note` | алгоритм (`plugin/i.kirka.dat:26-32`, `plugin/i.w.t.dat:10-16`) |
| `locations` | где стоят узлы в `content/locations`: стартовый `stock`, `regrowSeconds`, `stockMax` (14 жил, 11 деревьев) |

Алгоритм: перед попыткой, если `stock == 0` и `now > regrowAt`, то `stock = stockMax`. Если запас всё ещё 0 — «пусто»
(занятость уже поставлена). Успех: `stock − 1`, при достижении 0 `regrowAt = now + regrowSeconds`. Провал запас не тратит.
Узлы с `stock 0` и старым `regrowAt` в контенте восстанавливаются при первой попытке.

## `consumables` — еда и питьё

`use=i.f.*` → `plugin/i.f.dat`. Ключ — ID предмета.

| Поле | Смысл |
|---|---|
| `name` | имя |
| `hp`, `mana` | прибавка (из `heal_hp` / `heal_mana` предмета, пусто = 0), обрезается до максимума; журнал «Жизнь +N», «Мана +N» с фактической прибавкой |
| `leaves` | что выдаётся после употребления (`i.f.b.empty` только для `i.f.b.water*`, `i.f.dat:31`) или `null` |
| `busy` | 4 с (`i.f.dat:14`) |
| `curesPoisonSeconds` | только `i.b.antidot`: `char[17]` (время окончания яда) уменьшается на 300 (`plugin/i.b.antidot.dat:5-6`) |

Предмет тратится всегда, даже при полном здоровье. Сюда входят и сырьё (травы, корни, грибы, сырая рыба, мясо) — их тоже можно съесть.
Пустая бутылка `i.f.b.empty` не съедается: это `special` → `fillBottle`.

## Исправления

Где в PHP явная ошибка, в данных записано задуманное поведение:

1. **Рыбалка: улов без сообщения, статистики и опыта.** После цепочки `if … else` стоит `else if ($b)` (`i.fishman.dat:50-64`),
   блок «поймал» выполняется только когда ничего не поймано. В данных: при улове — сообщение «поймал …», `st[4]++` (`stat: 4`)
   и опыт 1 с шансом `rand(1,100) < 10` (9%), как написано в этом блоке.
2. **Рыбалка: «часть амулета» `i.q.ambroken1` недостижима.** Строка `:18` не входит в цепочку `else` (выдала бы два предмета),
   а порог `S*0,2 < 1` при `rand(1,200)` не выпадает никогда (навык максимум 5). В данных строка — первая в цепочке, а кость
   `rand(0,199)` вместо `rand(1,200)`: значение 0 даёт амулет при любом навыке ≥ 1 (0,5%). Остальные строки сохранили
   свои множители; общий шанс улова стал `20S/200` вместо `(20S−1)/200` (при 5 — 50% вместо 49,5%).
3. **Рыбалка: треуголка `i.a.k.h1` не существует** (`i.fishman.dat:33`), `additem` молча ничего не выдавал. В данных `i.a.h.k1`
   «треуголка» (слот головы).
4. **Удочка ломается 4% вместо заявленных 5%** (`rand(1,100) <= 4`, комментарий `:66` «фиксированная вероятность 5%»; у
   наборов ювелира `<= 5`). В данных `toolBreakPercent: 5`.
5. **Места у воды — по подстроке.** `strpos($loc_water1, $loc)` находит и ID-префиксы (`x1121x60` в `x1121x606`). В данных
   списки локаций, сравнение точное (удочка и наполнение бутылки).
6. **Коптилка при провале выдаёт пустую бутылку** (`i.set.koptilka.dat:39`, скопировано со ступки). В данных `failGives: {}`.
7. **Ступка корней `i.set.stupka.m` не даёт опыта** — копия `.h` без строки `addexp`. В данных `randUpTo 2`, как у `.h`.
8. **Живая вода.** Проверка «не призрак» сравнивает с `"0"`, пустое значение её проходит; затем при удачном броске
   воскрешение и списание делаются только при `char[8] == "1"`, иначе — тихо ничего (`i.ress.dat:10-18`). В данных `target.kind:
   playerGhost`: цель, которая не призрак, отклоняется до занятости и броска; живая вода тратится в обоих исходах.
9. **Заточка без занятости.** `i.z.w.dat:10` ставит `$char[6]`, но не записывает в `$l_i`, а `g.php:195` после `use`
   перечитывает `char` — пауза терялась. В данных `busy: 10`.
10. **Букет из двух разных цветов.** `i.bc.dat:25` читает количество второго цветка из `$l_i[$login]` (нет `$loc`) — всегда 0 —
    и не списывает его. В данных (`rules`): обе стопки целиком уходят в букет.

## Неоднозначное (оставлено как в PHP)

* Кожевник ставит занятость 0 (`char[6]=time()`, `i.set.currier.dat:25`), видимо забыто `+N`, но задуманное число неизвестно.
* Живая вода бросает `rand(1,200)`, бинт — `rand(1,100)` при той же формуле: возможно, намеренно реже.
* Извлечение самоцвета уничтожает предмет в любом исходе, шанс растёт с числом камней — выглядит намеренным.
* Ножницы режут на бинты и доспехи `i.a.b.*` (в том числе металлические) — слот `b` это корпус, не только одежда.
* Выпитое зелье `i.f.b.*` (кроме воды) не оставляет пустой бутылки, хотя делается из бутылки.
* Голем может появиться в банке `x1092x474`, но жилы там нет; `c.1.main` в списке мест самоцветов, но жилы там тоже нет — безвредно, оставлено.
* При нехватке ресурсов табличного крафта PHP вызывает `msg()` уже после записи занятости; сохраняется ли она, не проверено.
  Движку достаточно: при нехватке ничего не тратится и занятость не ставится.
* В `i.set.ar.dat:4-5` сообщения используют неопределённую `$item` (пустое имя) — в `messages` подставляется `{name}`.

## Проверка

При подготовке файла проверено скриптом: JSON разбирается; все ID предметов (ключи и значения, базовый ID до `_` / `..`)
есть в `content/items`, кроме `i.s.tkach` — ткацкий станок существует только как объект локации `x4x5` (определения в
`items/` нет и в оригинале); префиксы (`i.w.t.`, `i.h.p.*` …) совпадают хотя бы с одним предметом; `i.s.d.` — трупы, только во
время игры; NPC `n.c.gol` — в `content/raw/npc`; все локации воды и голема есть в `content/locations`; каждый `i.f.*`
покрыт `consumables` или `special`.
