# Тестовый запуск на Railway

Тестовое окружение запущено в проекте Railway `territory-evil-legacy-preview`. Стартовый экран сервера 1 отвечает по адресу https://territory-evil-php-production.up.railway.app/1/g.php: без Basic Auth возвращается HTTP 401, с настроенными `PREVIEW_USER` и `PREVIEW_PASSWORD` — HTTP 200 и HTML. Адаптер в `html-output.php` преобразует WML на выходе; оригинальная игровая логика остаётся в архиве. Проверены также HTML-ответы страницы регистрации и ещё одного экрана, но это не подтверждает работоспособность полного сценария регистрации или игры. Архив содержит PHP-код 2004–2007 годов и ссылки на сторонние старые адреса.

1. Создать в Railway приватный сервис `mariadb:10.11` с томом `/var/lib/mysql` и базой `game`. Стандартный шаблон Railway использует MySQL 9.4, с которым старый `mysql_*` несовместим.
2. Подключить репозиторий `zzzloj/Tz-` как веб-сервис, выбрать Dockerfile `railway-preview/Dockerfile`, build context — корень репозитория.
3. Передать сервису переменные `MYSQLHOST`, `MYSQLPORT`, `MYSQLUSER`, `MYSQLPASSWORD`, `MYSQLDATABASE` из MariaDB, а также отдельные `PREVIEW_USER`, `PREVIEW_PASSWORD`. Пароли не добавлять в репозиторий.
4. Добавить веб-сервису постоянный том с точкой монтирования `/data`. Он хранит игровой мир и файлы состояния между перезапусками.
5. Проверить логи запуска, затем открыть `/1/g.php` под Basic Auth. Действующий домен указан выше; пароль хранится только в приватных переменных Railway.

Изолированный стартовый тест включает сервер 1 и таблицу `users`; форум специально заблокирован, потому что полного дампа форума нет. Адаптер пропускает только внутренние ссылки и переносит введённые значения между страницами в пределах вкладки браузера. Оригинальная регистрация, авторизация и переход между серверами требуют дальнейшей проверки и правки старых URL. Исходные WML-файлы не переписаны в HTML.
