# Словарь полей данных «Территории Зла»

Справочник по всем строкам с разделителем `|` (и вложенным `:` / `,` / `=`) в движке `game/1`.
Нужен, чтобы выгрузить данные в JSON с именованными полями. Выгрузка сделана: данные теперь живут в `content/` (см. `content/README.md`), имена полей — в `tools/content/schema.json`; ниже описан формат файлов движка, которые собираются из `content/`. Все выводы сделаны по коду:
ссылки `файл:строка` указывают на `game/1/…`, номера строк считаются после `iconv -f cp1251 -t utf-8`.

Условные обозначения:

* **Тип**: `int`, `float`, `str`, `ts` (unix-время, int), `bool01` (пусто/0 = нет, иначе да), `list`, `special`.
* **R/S**: `S` означает статическое определение, `R` означает состояние, которое меняется во время игры
  (текущие HP, таймеры, цели и т.п.). При экспорте определений поля `R` можно отбрасывать или обнулять.
* **unknown** означает, что назначение по коду установить не удалось (поле нигде не читается или всегда пустое).

Общие правила разбора:

* Файлы в кодировке cp1251. Файлы `items/*` читаются как `explode("|", implode("", file(...)))`, поэтому
  **перевод строки в конце файла попадает в последнее поле** (например `…|5:5|1\n`). При экспорте нужен `trim`.
* Пустое поле и `0` для движка одно и то же (PHP-ложь). Хвостовые пустые поля (`|||`) ничего не значат.
* В некоторых строках часть кириллицы заменена похожими латинскими буквами (`кулaкaми`, `мaгиeй`, `вoлк`).
  Раньше так экономили WAP-трафик. `f_attackf.dat:28` явно нормализует `мaгиeй` в `магией`. Перед сравнением
  значений их нужно нормализовать.

## 0. Грамматика идентификаторов

ID сущности кодирует класс и часто данные экземпляра. Базовый ID (имя файла в `items/`) получается
отрезанием всего после первого `_`, а если его нет, то после первого `-` (`f_lookitem.dat:3-4`,
`f_calcparam.dat:30-31`, `f_additem.dat:9-10`).

| Шаблон | Смысл | Где |
|---|---|---|
| `i.<base>` | предмет | |
| `i.<base>_<maker>_` | предмет, изготовленный игроком `<maker>` (логин без `u.`; сам может содержать `_`, берётся от первого до последнего `_`) | `f_lookitem.dat:68` |
| `…-<N>-` | заточка +N (в бою даёт +N к мин./макс. урону, но не больше 6) | `f_lookitem.dat:65`, `f_calcparam.dat:69-70` |
| `…..<g1>..<g2>..<g3>` | инкрустированные самоцветы; `<g>` это суффикс `items/i.i.<g>` | `f_lookitem.dat:69`, `f_calcparam.dat:74-86` |
| `i.bc_<maker>_<c1><n1><c2><n2>…` | букет: буква `c` означает `items/i.bc.<c>`, `n` это количество | `f_lookitem.dat:70` |
| `i.ms_<npc_id>[_<translit_name>]` | свиток призыва конкретного NPC | `f_lookitem.dat:36` |
| `i.rr.<loc>` / `i.rr.empty` | руна телепорта в `<loc>`. **Файл `items/i.rr.*` не читается**: имя и цена всегда жёстко `руна|50` | `f_lookitem.dat:5,35`, `f_additem.dat:11` |
| `i.s.portal_<loc>` | портал в локацию `<loc>` | `f_lookitem.dat:13` |
| `i.s.d.<victim_id>.<5..99>` | труп | `f_kill.dat:11-12` |
| `i.a.<slot>.<…>` | броня. Слот определяют первые 6 символов (`i.a.b.`, `i.a.h.` …), в каждом слоте один предмет | `plugin/i.w.dat:25-31` |
| `i.w.<…>` | оружие; `i.w.r.` стрелковое/метательное, `i.w.k.` нож (разделка трупов), `i.w.t.` топор (рубка), `i.w.u.`/`i.w.s.` посохи/мечи | `f_lookitem.dat:48-52` |
| `m.<…>` | заклинание; `m.w.` боевое, `m.w.a.` по площади, `m.s.` призыв, `m.heal*` лечение | `f_usemagic.dat:49-54` |
| `p.<…>` | боевой приём; `p.d.*` защитный | `f_usepriem.dat:19,28` |
| `u.<login>` | игрок | |
| `n.<…>` | NPC. Класс по префиксу (см. §3.4) | |
| `x<X>x<Y>` | локация на карте; `c.<N>.*` замок N; `z.*` комнаты/хранилища; `_begin`, `_begi`, `arena` | `g.php:246, 265` |

Слоты брони, встречающиеся в данных: `a` (аксессуар: галстук, фата), `b` (корпус), `c` (обувь), `d` (серьга/орден),
`e` (плащ), `h` (голова), `k` (кольцо), `l` (ноги), `m` (амулет/ожерелье), `n` (браслет), `o` (очки), `p` (руки), `r` (рубашка/платье),
`s` (щит), `w` (штаны). Щит несовместим со стрелковым оружием (`plugin/i.w.dat:13-31`).

## 1. Определения предметов: `items/i.*`, `items1/*`

Общее ядро для всех классов:

| idx | key | Смысл | Тип | Код |
|---|---|---|---|---|
| 0 | `name` | отображаемое имя | str | везде: `$item[0]` |
| 1 | `price` | базовая цена в монетах. Покупка у NPC стоит `price*buy_mult`, продажа `price*sell_mult`. При `price<=1` множитель принудительно 1 | int | `f_speakbuy.dat:27`, `f_speakbuyto.dat:15-18`, `f_speaksell.dat:27`, `f_speaksellto.dat:25-26` |

Остальные поля зависят от класса.

### 1.1 `i.a.*` — броня

Пример: `бронзовый доспех|290|4|4:3`

| idx | key | Смысл | Тип | Код |
|---|---|---|---|---|
| 2 | `armor` | величина брони; для `i.a.s.*` (щит) это «броня щита», в бою вычитается при удачном парировании | int | `f_calcparam.dat:45-46`, `f_lookitem.dat:38` |
| 3 | `req` | требования `str:dex:int`. Каждая недостающая единица str/int снимает 2 брони, dex снимает 10% меткости | special `int:int:int` | `f_calcparam.dat:36,40-46`, `f_lookitem.dat:39` |
| 4 | `unknown_4` | **unknown**. Встречается только у 29 предметов, значения `0/1/2` (2 у палладинских вещей, 1 у адамантовых/шипованных, 0 у «магических»). Код его не читает | int | не найдено |

Скрытые правила в коде (в данных их нет):
* комплектные бонусы (адамантовый сет, сет огра/тролля) жёстко заданы в `f_calcparam.dat:100-102`;
* `i.a.m.vlast` удваивает урон по `n.c.*` (`f_attackf.dat:73-74`).

### 1.2 `i.w.*` — оружие

Пример: `охотничий лук|150|4|10|3:3|5|из лука|i.arrow`

| idx | key | Смысл | Тип | Код |
|---|---|---|---|---|
| 2 | `dmg_min` | минимальный урон | int | `f_lookitem.dat:53`, `f_calcparam.dat:62-66` |
| 3 | `dmg_max` | максимальный урон | int | то же |
| 4 | `req` | `str:dex:int[:hp]`. Четвёртое значение «требует жизни» только отображается (`f_lookitem.dat:56`), в расчётах не участвует. Штраф: -2 урона за единицу str (у посохов -4/-5 за int) | special | `f_calcparam.dat:37-42,61-67` |
| 5 | `speed` | базовая пауза между ударами, сек; итог `war[3] = speed - round(dex/2)`, минимум 3 | int | `f_calcparam.dat:50`, `f_lookitem.dat:59` |
| 6 | `verb` | творительный падеж для журнала («мечом»). **Значения `магией` и `молнией` переключают атаку на магическую ветку** (уклон/сопротивление от магии, броня не действует) | str | `f_calcparam.dat:52,61`, `f_attackf.dat:30` |
| 7 | `ammo` | ID расходуемого боеприпаса (`i.arrow`, `i.bolt`); у метательных это сам предмет. Пусто, если ничего не расходуется | str (item id) | `f_calcparam.dat:54,58`, `f_attackf.dat:66-70`, `f_lookitem.dat:60-62` |

Урон от силы: к min/max прибавляется `str`, кроме арбалетов `i.w.r.c.` (`f_calcparam.dat:71`).

### 1.3 `i.f.*` — еда и напитки

Пример: `элексир исцеления|250|25|20`

| idx | key | Смысл | Тип | Код |
|---|---|---|---|---|
| 2 | `heal_hp` | +HP при использовании | int | `plugin/i.f.dat:16-21`, `f_lookitem.dat:46` |
| 3 | `heal_mana` | +мана | int | `plugin/i.f.dat:22-27` |

Особые ID: `i.f.b.empty` наполняется у воды (список локаций в `plugin/loc_water`), после `i.f.b.water*` остаётся `i.f.b.empty` (`plugin/i.f.dat:4-11,31`).

### 1.4 `i.i.*` — самоцветы (также в `items1/`)

Пример: `хризолит|60|10:10,11:10,5:-5,54:-5|Сопр. магии +10%, Броня -5, Мана -5`

| idx | key | Смысл | Тип | Код |
|---|---|---|---|---|
| 2 | `effects` | список `stat:delta` через `,`. Если `stat < 50`, это индекс в `war` (§3.2), если `stat > 50`, это индекс в `char` = `stat-50` (52 = max HP, 54 = max mana). Одинаковые камни на разных вещах не суммируются | list of `int:int` | `f_calcparam.dat:77-85` |
| 3 | `description` | текст эффекта для игрока | str | `f_lookitem.dat:11,69` |

Используемые индексы: `0` меткость, `1`/`2` мин./макс. урон, `3` пауза атаки, `5` броня, `6` уклон, `7` парирование,
`9` маг. уклон, `10` маг. парирование, `11` маг. сопротивление, `52` max HP, `54` max мана.

**Описания часто расходятся с данными:**
* `i.i.gt` `3:10` означает +10 сек паузы атаки, а в описании «навык некромантии +10%»;
* `i.i.kp`, `i.i.kr` `54:10` дают +10 маны, а в описании «критический урон +5%». Крит от `..kp` на самом деле жёстко задан в коде (`f_attackf.dat:99`);
* `i.i.fa`/`i.i.jd`/`i.i.ld` `2:5` означают макс. урон +5, а в описании стихийный урон или сопротивление;
* `i.i.do` штрафует меткость на 20 в коде (`f_calcparam.dat:110`), в данных этого нет;
* `..ma`/`..ne` дополнительно учитываются в `plugin/m.man.dat:9-10`.

### 1.5 `i.m.*` (свитки) / `i.r.*` (руны заклинаний)

`свиток Лечение|20`. Поля 0-1 из общего ядра. Эффект берётся из `m.<тот же суффикс>`: `i.m.heal` вызывает `m.heal`.

## 3. Сущности: NPC-шаблоны `npc/n.*` и живые записи в `l_i/*`

`npc/<id>` — PHP-файл, который присваивает `$npc = array(...)` и подключается через `include`
(`f_timernpc.dat:8`, `f_kill.dat:76`). Три шаблона (`n.c.gnomt`, `n.c.gol`, `n.c.her`) **содержат код с `rand()`**:
имя, «оружие» и добыча выбираются случайно. Для экспорта их нужно исполнять или разбирать вручную.

Ключи шаблонов (сколько файлов из 308): `char` 308, `war` 308, `items` 105, `equip` 93, `itemsrnd` 93, `osvej` 60, `bank` 45, `h_t/h_s/h_p/h_v1/h_v2` 1.

## 4. Локации: `l_i/*`, `l_t/*`, `l_f/*`

* `l_i/<loc>` — **живое состояние** (сериализованный PHP-массив), перезаписывается при каждом сохранении (`g.php:322-331`).
* `l_t/<loc>` — **эталонная копия мира** того же формата. Движок читает её, только если `l_i/<loc>` не разобрался даже после
  починки `calcser` (`g.php:621-625`). Из 1374 файлов 119 пустые (0 байт). Все файлы из `l_t` есть и в `l_i`; ещё 31 локация `c.*` и `z.*` есть только в `l_i`.
* Починка: `preg_replace_callback('/s:\d+:"(.*?)";/', calcser)` пересчитывает длины строк (`g.php:622,682`). 99 файлов `l_i/z.*` и других без неё не разбираются.
  Длины в них, видимо, сбиты перекодировкой. Регулярка не жадная и **ломается, если внутри строки встречается `";`**.

Ключи верхнего уровня (скан всех файлов): только `d`, `i`, `t` (в `l_i`: `d` 970, `d,i` 288, `d,i,t` 80, `d,t` 67;
в `l_t`: `d` 924, `d,t` 276, `d,i` 35, `d,i,t` 13). Ключ `save` может появиться в памяти (`f_admin.dat:61`, `f_castlein.dat:48`), но на диск не пишется.

### 4.2 `t` — таймеры

Массив `ключ => значение`. Ключ — unix-время срабатывания. В `l_t` и `F_blank.dat` ключи — маленькие числа (1, 2, 15…),

| Вид значения | Формат | Смысл | Код |
|---|---|---|---|
| NPC-строка | `npc_id|resp_min:resp_max[:snap]|[wander_steps:tmin:tmax[:next_ts]]` | заспавнить NPC. `[1]` уходит в `war[15]` = `loc:[1]`, `[2]` в `char[10]` | `f_timernpc.dat:2-12` |

## 5. Списки предметов (`items`, `bank`, `equip`, `osvej`)

* **item list**: `id:count|id:count|…`. `id` может содержать суффиксы из §0. Поиск количества идёт регуляркой
  `/.*<id>:(\d+).*/`, **без экранирования точек и без границ слова**, так что `i.a.b.c` может совпасть внутри `i.a.b.c1`.
  Повторяющиеся или пустые `||` движок схлопывает (`f_additem.dat:49-51,104-106`).
* **trader stock** (`bank` торговца): `chance:min:max=id:count|…` (§3.5). Позиции с `=` при нуле не удаляются (`f_additem.dat:68`).
* **equip**: `id|id|…` без количеств; каждый id обязан присутствовать в `items` (`f_calcparam.dat:32`).
* **itemsrnd**: `id:chance:min:max|…`.
* В трупе те же списки с разделителем `,`.

## 7. Сводка: статика и состояние

* **Статические определения**: `items/*` (кроме `m.man.dat`, `n.c.*`), `items1/*`, `npc/*` (кроме блоков `rand`), `speak/*`,
  `desc/*`, `l_f/*`, `l_t/*` (эталон), `plugin/loc_water`, `F_blank.dat`.
* **Состояние (runtime)**: `l_i/*` (целиком), `game.dat`, `online/*`, `count.dat`, `on.dat`, `glast.dat`, `quest/quest.demon`.
* Внутри `l_i` к статике относятся только `d[0]` (кроме ворот замков), `d[1]`, большинство выходов и поля NPC `char[0,2,4,8]`,
  `war[0..14]`. Всё остальное меняется во время игры.
