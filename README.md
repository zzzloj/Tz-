# Территория Зла (WAP RPG)

Исходники старой WAP-игры «Территория Зла» (PHP, ~2007 г., движок на базе «Амулета Дракона»), перенесённые на PHP 8.4.

Источник: архив «Территория Зла» с masteram.us (раздел «Скрипты → Онлайн игры», файл №96,
`KODERAM.INFO_1721_Zlo_2.zip`), залит на сайт пользователем Mayk 30.04.2014. Первый коммит репозитория — архив как есть.

## Структура
- `game/` — скрипты игры: портал в корне, серверы `1/` и `2/` (движок `g.php`), плагины в `plugin/`
- `content/` — данные мира в UTF-8 JSON: предметы, NPC, диалоги, локации. Из них при сборке получаются файлы движка в `game/1/` (см. `content/README.md`, поля — `docs/data-fields.md`)
- `docs/` — справочники: `data-fields.md` (значения полей данных), `quests.md` (каталог 53 квестов, их логика и ошибки)
- `tools/content/` — сборщик `build.py`, разовый экспортёр и проверка круга
- `game/lib/` — переходный слой для PHP 8 (см. ниже)
- `sql/table.sql` — схема таблицы из архива
- `railway-preview/` — сборка для Railway (PHP 8.4 + Apache, WML-рендерер), подробности в `railway-preview/README.md`

## Перенос на PHP 8
Код переведён механически, инструментами на токенизаторе PHP, с проверкой на эталоне (оригинал на PHP 5.6):
- `$s{0}` → `$s[0]`, `preg_replace(.../e)` → `preg_replace_callback`, `ereg*`/`split`/`each`/`session_register`/`convert_cyr_string` → современные аналоги, `$HTTP_*_VARS` → суперглобальные массивы, `parse_str($x)` → `parse_str($x, $arr); extract($arr)`, короткие теги `<?` → `<?php`;
- `count()`, `implode()`, `in_array()`, `array_*()` получают `(array)(...)`: PHP 8 бросает `TypeError` на `null`/`false`;
- `lib/legacy.php`: `legacy_num()` и `legacy_cmp()` возвращают числовую семантику PHP 5/7. Движок считает на пустых полях персонажей (`"a||c"`), а PHP 8 бросает `TypeError` на `"" + 1` и считает `"" == 0` ложью. Операнды арифметики, составные присваивания, сравнения с числами и числовые параметры функций обёрнуты автоматически;
- `lib/mysql_compat.php`: API `mysql_*` поверх `mysqli` (соединение в `cp1251`, как таблицы).

## Атомарная запись мира
Файлы состояния (локации `l_i/`, `online/`, кланы, счётчики) раньше перезаписывались на месте: `fopen('w')` обнулял файл, затем шла запись — процесс, убитый между этими шагами (деплой, OOM), оставлял пустую или обрезанную локацию («Нет данных», пропавшие вещи). Теперь `fopen(..., 'w')` → `legacy_fopen_w()`: запись идёт во временный файл рядом, `fclose` (или конец запроса) атомарно подменяет им целевой через `rename()`. Запросы сериализуются блокировкой `game.lock`, `game.dat` сохраняется через `legacy_atomic_write()` и читается целиком (раньше — только первые 64 КБ). Временные файлы, оставшиеся после сбоя, удаляются при старте контейнера.

`legacy_num()`/`legacy_cmp()` и `mysql_compat.php` — временные: при рефакторинге их заменят настоящие типы и PDO.

Не перенесено: форум (`forum/`) — нет дампа базы, и он не работал уже на PHP 5.6. Удалены мёртвые недописанные файлы из архива, на которые ничего не ссылалось и которые не проходили даже синтаксическую проверку (`f_newpass.dat`, `2/f_say1.dat`, корневые `f_site_clan.php` и `f_site_list.php`), и редакторские копии `*~`. Смена пароля работает через портал (`f_site_main2.dat`).

## Отличия от оригинала
- Кириллица больше не заменяется похожей латиницей на выходе (`strtr("КЕНХВАРОСМТехарос", "KEHXBAPOCMTexapoc")` в `g.php` и `f_ip.php` экономил WAP-трафик). Смешанные слова, которые авторы вписали в тексты вручную (≈2500), остались — их стоит нормализовать при выгрузке мира.
- Фильтры ввода пропускают «Ё/ё» (раньше диапазон `А-я` в cp1251 их не включал, и буква вырезалась из чата и сообщений).

## Предупреждения
- Файлы в кодировке windows-1251.
- Пароль БД в `config.ssp` (×3) и `forum/config.inc.php`, а также пароль админа форума в `forum/system.php` заменены на `CHANGE_ME`. На Railway `config.ssp` перезаписывается из переменных окружения при старте.
- Мастер-ключ админки (`zx=mda`) и захардкоженные админские ники оставлены для тестирования — см. `claude/todo.md` в проекте перед открытием доступа.

## Запуск
Сервис `territory-evil-php` в Railway-проекте `territory-evil-legacy-preview` собирается из ветки `main` по `railway-preview/Dockerfile` (build context — корень репозитория). Нужны MariaDB 10.11 и том `/data`, см. `railway-preview/README.md`.

## Миры
В оригинале два мира: код продублирован в `game/1` и `game/2`, у каждого лимит онлайна (`$g_max`), и персонаж мог переходить между мирами с имуществом (в этом архиве перенос не реализован: `f_newserver.php` только выводит список серверов). Лимит был вызван файловым хранением мира с одной блокировкой на все запросы.

Решение (28.09.2026): **один мир.** Второй мир закрыт (`/2/` запрещён в `apache.conf`, убран из «Списка серверов»), код оставлен до рефакторинга. Для нового движка:
- рост нагрузки решается в движке (состояние в БД, блокировки по локациям), а не копиями мира;
- у персонажа с самого начала есть идентификатор мира, даже пока мир один;
- персонаж вместе с инвентарём — отдельная единица данных, так что перенос или сезонные миры потом можно добавить как админскую операцию.

## Тесты
`bash tests/run.sh`: линтер, проверка контента, сквозной сценарий игрока в браузере, случайный обход тремя игроками с проверкой целостности файлов мира и дифференциальный тест «предыдущий коммит против текущего». GitHub Actions запускает его на каждый push в `main` и на pull request. Подробности и локальный запуск — в `tests/README.md`.
