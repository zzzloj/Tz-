# Прогрессия персонажа и небоевые навыки

Описание того, как это реализовано в движке `game/1` (а не того, как задумано или написано в справке).
Ссылки `файл:строка` указывают на `game/1/…`, номера строк считаются после `iconv -f cp1251 -t utf-8`.
Имена полей (`char[1] hp`, `skills[24] mining`, `war[13] exp_value`, `owner` …) взяты из `docs/data-fields.md`.
Там же описаны форматы данных, здесь они не повторяются. Квесты описаны в `docs/quests.md`. Формулы боя (попадание,
урон, магия, смерть) описаны отдельно; здесь они упоминаются только там, где влияют на прогрессию.

Общие обозначения:

* `S(n)` — значение `skills[n]` игрока. Все навыки и атрибуты целые, 0..5 (атрибуты 1..5).
* `rand(a,b)` в PHP включает обе границы. Поэтому проверка `rand(0,100) < X` даёт вероятность `X/101`, а
  `rand(1,100) < X` даёт `(X-1)/100`. В таблицах ниже для простоты указано `X%`, точная форма проверки приведена в тексте.
* «Занят» — `char[6] busy_until`. Пока `time() <= char[6]`, любое `use=` (предмет, заклинание, приём, навык)
  отклоняется сообщением «Вы должны отдохнуть N сек» (`g.php:186-198`). Если `char[6]` больше чем на 120 с в будущем,
  он сбрасывается (`g.php:186`). Перемещение (`go=`) эту проверку не проходит, ходить можно и «занятым».
* Сообщения в журнал «X сделал …» для всех в локации опущены, если не важны.

## 2. Новый персонаж

### 2.1 Регистрация

Есть две формы:

* **Внутриигровая** (`f_connect.php:53-62`). Если центральная база (`GetData`, `datafunc.php`) знает логин и пароль,
  но персонажа ещё нет («Данные не найдены»), игрок выбирает пол и возраст (2 цифры) и переходит на `site=reg2`.
* **Сайт** (`f_site_reg.dat:1-19`). Пол, дата рождения в виде `31/12/2009`, город, «о себе». Отправляет на тот же `reg2`.

`f_site_reg2.dat` создаёт запись:

* проверки: все поля заполнены (`:2`), `age = intval(age)` в диапазоне 5..99 (`:4-5`), пол из одной буквы (`:6`);
  логин приводится к `u.<login>` в нижнем регистре (`:7-9`); персонажа ещё нет в базе (`:13-15`);
* стартовая локация `_begin` (`:17`);
* запись игрока (`:20-28`):

| Ключ | Стартовое значение | Смысл |
|---|---|---|
| `user` | `пароль||пол|возраст||now|0|0|0|0|0` | |
| `char` | `Имя|20|20|20|20|1|1||0|0|0||` | HP 20/20, мана 20/20, `regen_ts=1`, `busy_until=1`, не призрак, не преступник |
| `skills` | `1|1|1|0|2|0|…|0` (32 поля) | `str=dex=int=1`, `exp=0`, **`skill_points=2`**, все навыки 0 (поля 32-33 появятся при первом обучении, `f_speakskillup.dat:135-136`) |
| `items` | `i.w.k.begin:1` | «нож» (урон 0-2, пауза 4). Не надет. Это нож класса `i.w.k.`, им можно свежевать трупы (§4.8) |
| `magic` | пусто | |
| `war` | считается `calcparam` (`:33`) | |

* `st` (статистика) при регистрации не создаётся. Её создаёт первый вход: `f_site_connect2.dat:82-94` дописывает 12 нулей.
* Оплаченный период: `now + freedays*86400` (`:42-44`). Счётчик регистраций хранится в `../all.dat` (`:47-52`).

### 2.2 Стартовая зона

`_begin` «Переулок» — охраняемая зона (`zone=1`). Выходы: север `x1141x506` (двор лекаря), восток `x1185x526` (магазин),

## 3. Опыт и очки опыта

### 3.1 Навыки не растут от использования

В движке **нет прокачки навыков действием**. Любое действие (рубка, рыбалка, крафт, убийство) даёт только
общий опыт `skills[3] exp`. Когда опыт превышает порог, игрок получает 1 **очко опыта** `skills[4] skill_points`.
Очко тратится у учителя-NPC на +1 к выбранному навыку или атрибуту (§3.4).

### 3.2 Начисление: `addexp()` (`f_addexp.dat`)

```
if exp == 0: return                                   (:4)
skills[3] += exp; журнал «Опыт +exp»                  (:8-9)
if skills[3] > war[13] * g_exp:                       (:10)
    skills[3] = 0; skills[4] += 1; «Вы получили 1 очко опыта!»
if skills[3] == 0: calcparam()                        (:12)
```

* Только для игроков (`u.`, `:5`).
* **Излишек опыта сгорает** (`skills[3]=0`, а не `-=порог`), и за одно событие можно получить не больше 1 очка.
* `war[13]` у игрока — сумма всех `skills` кроме `[3]`, **включая неизрасходованные очки `[4]`**
  (`f_calcparam.dat:21`). Трата очка у учителя сумму не меняет (+1 навык, -1 очко), поэтому порог растёт на 10
  с каждым **заработанным** очком: у нового персонажа `war[13]=5`, первое очко даётся при опыте `> 50`, k-е — при `> (4+k)*10`.
  До предела навыков (`12+50=62`, то есть 57 заработанных очков) нужно около 18 900 опыта.
* Обмен через `skilldown` (§3.4) уменьшает сумму на 1, то есть снижает порог.

Тот же код продублирован для убийств:

* игрок убил NPC: `skills[3] += war[13] жертвы` (поле `exp_value` шаблона), та же проверка порога (`f_kill.dat:105-112`).
  За убийство игрока опыта нет (`:97-104` только записывает `pk_record`);
* NPC `n.s.*` / `n.z.*` / `n.a.*` с хозяином убил NPC: половина `exp_value` идёт игроку `owner[1]` — **тому, за кем
  питомец следует**, а не хозяину `owner[0]` (`f_kill.dat:115-135`). Наёмники (`n.kastle*`), стража замка `n.o.*` и фея
  опыт не передают.

### 3.4 Трата очков: учителя (`f_speakskillup.dat`)

Тема диалога, текст которой начинается с `skill`, вызывает обучение (`f_speak.dat:47`). Формат `skill|<что>|cost|min|max`
(`:4-8`); `eval:`-тема может вернуть такую строку по условию.

**Заклинание `m.*`** (`f_speakskillupm.dat`) и **приём `p.*`** (`f_speakskillupp.dat`) подключаются раньше всех проверок
(`:11-12`), поэтому **очков опыта не требуют**, только денег. Заклинание: не выучено (`m:4`), `min <= S(13) magic <= max`
(`m:5-6`), оплата `cost` (`m:7-11`), добавляется в `magic` с кулдауном 1 (`m:12`). Приём: не выучен (`p:4`), оплата (`p:5-9`);
**`min/max` у приёмов игнорируются**. Скидки новичку на заклинания и приёмы нет.

**Навык или атрибут**:

1. Имя из таблицы `arr_skills` (`:17-50`), иначе ошибка (`:88`). Ключи: `str dex int meditation steal animaltaming hand
   coldweapon ranged parring uklon magic magic_resist magic_uklon regeneration hiding look steallook animallore spirit
   healing alchemy mine smith lumb bow stone fish food necro currier weaver`.
2. Нужно `skills[4] >= 1` (`:89`).
3. `min`: текущее значение `>= min` (`:90`). `max`: текущее значение `<= max`, то есть учитель поднимает максимум до `max+1` (`:91`).
4. Атрибут: значение `< 5` (`:95`). Если `str+dex+int >= 12`, нужно выбрать, какой атрибут понизить (`skilldown`, `:98-104`),
   понижаемый должен быть `>= 2` (`:97`).
5. Навык: значение `< 5` (`:106`). Если сумма 31 навыка `>= 50`, нужно выбрать, какой понизить (`:109-120`), понижаемый `>= 1` (`:108`).
6. Цена: если `cost` не 0 и сумма навыков без опыта `lev == 5`, обучение **бесплатное** (`:127`), иначе списываются монеты (`:129-131`).
   `lev` у нового персонажа 5 и при трате стартовых очков не меняется, поэтому бесплатны именно 2 стартовых очка.
7. `+1` навыку, `-1` понижаемому, `-1` очку, `calcparam` (`:138-142`).

Итого: атрибуты 1..5 с суммой не больше 12 (например 5/5/2); навыки 0..5 с суммой не больше 50 (не больше 10 навыков на максимуме).
При упоре в предел можно «переучиваться», понижая другой навык.

### 3.6 Отображение уровня

* Экран навыков: «Опыт: `skills[3]`/`war[13]*g_exp`», «Очки опыта» (`f_listskill.dat:81`). Навыки с нулевым значением не показываются (`:96`).
* Осмотр игрока: `lev = round((сумма skills кроме [3] и [4] − 5) * 100 / (g_attr+g_skills))`, то есть процент от `62`
  (`f_lookuser.dat:71-73`). Ранги (`:77-87`): <5 Новичок, 5 Начинающий, 10 Умелый, 20 Опытный, 30 Искусный, 40 Профессионал,
  50 Известный, 60 Знаменитый, 70 Мастер, 80 Грандмастер, ≥90 Лорд. У нового персонажа `lev = round(-200/62) = -3`.
* Титул по лучшему навыку (`:90-116`): боец(8), воин(9), лучник(10), маг(13), монах(5), укротитель(7), маскировщик(17),
  спиритуалист(21), повар(30), рудокоп(24), кузнец(25), лесоруб(26), плотник(27), ювелир(28), рыболов(29), лекарь(22),
  алхимик(23), некромант(31), вор(6), друид(32). При равенстве побеждает навык, стоящий в списке позже (`>=`). Если все нули, «боец».
  Не участвуют: ткач, осторожность, подглядывание, изучение животных, регенерация, парирование, уклон, сопротивления.

## 4. Здоровье, мана, отдых

### 4.1 Максимумы (`f_calcparam.dat`)

* `hp_max = 10 + str*10` (`:10`), +10 держателю флага лидерства (`:11`);
* `mana_max = 10 + int*10` (`:12`);
* самоцветы с эффектами `52:x` / `54:x` прибавляют к `char[2]` / `char[4]` (`:74-86`);
* комплекты: адамантовый сет (`i.a.h.ms`, `i.a.b.sborn`, `i.a.p.ms`, `i.a.l.ms`, `i.w.s.master`) +5 HP, +5 маны (`:100`);
  сет огра/тролля (+голова волка) +5 HP, +5 маны (`:102`);
* текущие HP/мана обрезаются до максимума (`:125-126`);
* заклинания `m.str`/`m.man` временно ставят `hp_max`/`mana_max = 10 + str|int цели * 10 + int заклинателя * 2`
  (`plugin/m.str.dat:8`, `plugin/m.man.dat:8`). Держится до следующего `calcparam`.

`calcparam` вызывается при смене экипировки, обучении, получении очка, смерти, посадке на лошадь и т.п.

### 4.2 Регенерация (`doai`, `g.php:569-579`)

`doai()` выполняется на каждый запрос любого игрока для его локации и соседних (`g.php:148-151`). Для каждого NPC и живого игрока
(у призрака `char[8]` регенерации нет):

```
tm = now - char[5] (regen_ts)
if tm > 30 and (отравлен или HP < max или мана < max):
    if не отравлен: HP   = min(HP + round(tm / (30 - 4*S(16) regeneration)), hp_max)      (:575)
    else:           HP   = max(HP - round(tm / 10), 1)                                     (:576)
                    mana = min(mana + round(tm / (30 - 4*S(5) meditation)), mana_max)       (:577)
    char[5] = now
```

У NPC `S(5)=S(16)=0` (`:573`). Примерная скорость в минуту: 2 / 2,3 / 2,7 / 3,3 / 4,3 / 6 единиц для навыка 0..5.
Яд снимает около 6 HP в минуту, но не опускает ниже 1.

`char[5]` также сбрасывается:
* каждым попавшим ударом по цели (`f_attackf.dat:104`), поэтому под атакой (удар хотя бы раз в 30 с) регенерации нет;
* при входе в игру (`f_site_connect2.dat:102`), поэтому офлайн HP не восстанавливаются;
* при воскрешении (`f_ressurect.dat:8`), заклинаниях `m.meditation`, `m.str`, `m.man`.

### 4.3 Медитация (навык, `use=skill.meditation`, `f_useskill.dat:6-14`)

* нельзя при полной мане или навыке 0 (`:7-8`); занят 5 с (`:9`);
* шанс: `rand(0,100) <= S(5)*12 + z`, где `z=25`, если «время» из `f_time.dat` между 06.00 и 11.00, иначе 0 (`:11-13`);
* успех: `+rand(1, S(5))` маны, не выше максимума. Провал: «Медитация прервалась».

Это даёт от 1 до 5 маны раз в 5 с. **`f_time.dat` вычисляет не текущее время**: часы, минуты и секунды умножаются на 11 и
передаются в `mktime` (`f_time.dat:2-3`). Получается псевдослучайное «время», и бонусы по времени суток (медитация,
приручение) включаются хаотично, примерно на четверть суток.

Заклинание «Медитация» `m.meditation` (учат Antonio и Auron) переводит все HP сверх 1 в ману с коэффициентом 0,7 и
ставит HP=1 (`plugin/m.meditation.dat:4-12`).

### 5.1 Кража (steal 6), подглядывание (snooping 19), осторожность (awareness 18)

### 5.2 Скрытность (hiding 17)

Пассивный навык, работает в трёх местах:

* **агрессия монстров**: при каждом `doai` игрок попадает в список целей `n.c.*` и NPC-преступников, только если
  `rand(0,100) > S(17)*6` (`g.php:552,598`). При навыке 5 примерно 30% тиков игрок невидим для выбора цели;

* **незаметный уход**: с шансом `rand(1,100) <= S(17)*8` в журнал локации не пишется «X ушёл на …» (`g.php:132,135-136,644`).

### 7.2 Диалог с подчинённым (`f_speakowner.dat`)

Доступен, только если `owner[0] == login` (`f_speak.dat:14-16`); у `n.o.*` и `n.q.*` свои диалоги.

* **Сесть в седло** (только `n.a.losh.*`, `:16-31`): не призрак, не верхом, не занят; `char[12] mount = "1:<HP лошади>"`, занят 3 с,

  может быть и `owner[1]`.
* **Защищай меня / Не лезь в драку / Защищай…** — `owner[2]` (`:32-60`). При выборе чужого: не больше 3 подчинённых, связанных с

* **Атакуй…** — `char[7]` питомца (`:61-82`). Нападение на непреступника или на животное в охраняемой зоне делает хозяина

* **Следуй за мной / Стой здесь / Следуй за…** — `owner[1]` (`:83-112`), «Следуй за…» ставит и `owner[2]`. Лимит тот же, 3.
* **Изменить имя** (`n.a.`, `n.z.`, `n.s.`): до 10 символов, транслит (`:113-135`).
* **Приласкать** (`:137-148`): только если до ухода меньше 4 мин; занят 10 с; шанс `rand(0,100) < S(7)*10`; успех продлевает
  `owner[3]` на `rand(60, 60+S(20)*60)` с. Бессрочным «нет нужды».
* **Состояние** (`:150-162`): оценка времени до ухода с погрешностью `rand(0, 10*(10−2*S(20)))%` (при lore 5 точно).
* **Нам пора расстаться** (`:163-168`): уходит домой `owner[6]`, либо исчезает (`owner[4]`), либо становится диким.

### 7.3 Поведение (`f_owner.dat`, вызывается из `doai`, `g.php:590`)

* если подчинённый преступник, хозяин в той же локации тоже становится преступником (`:5`);
* **уход**: если `owner[3]` истёк, или **1 час без перемещения** (`owner[5]`, ставится при первом проходе и при каждом шаге за
  хозяином; в замках `c.*` не действует) (`:11,15`). Подчинённый уходит в `owner[6]`, в точку респауна `war[15]` или исчезает
  (`:15-27`). Поэтому купленные «бессрочные» животные тоже уходят, если их оставить на час;
* **фея** `n.he.*`: раз в `h_p` = 20 с лечит хозяина в текущей локации на `rand(h_v1,h_v2)` = 5..15 HP, если он ранен (`:29-33`);
* **следование**: если цель `owner[1]` в соседней локации, подчинённый переходит туда (`:36-63`). Не идёт за призраком (`:46`);
  не идёт, если там уже больше 3 NPC, в `owner` которых встречается цель (`:47-50`, фактически пропускает до 4);
  стража `n.o.` не выходит из замка и не идёт туда, где уже 5 стражников (`:38-45`);
* **охрана**: если кто-то атакует `owner[2]` (или его подчинённого), подчинённый атакует его. В охраняемой зоне не
  вступается за преступника (`:67-72`).

Опыт за убийства — §3.2 (только `n.s.`, `n.z.`, `n.a.`).

## 8. Странности и ошибки

**Прогрессия**

1. Излишек опыта сгорает при получении очка, за одно событие максимум 1 очко (`f_addexp.dat:10`, `f_kill.dat:109,132`).
2. Неизрасходованные очки входят в `war[13]` и повышают порог (`f_calcparam.dat:21`). Трата очков на фею (`n.w.Mihail`)
   и обмен через `skilldown` порог понижают.

**Небоевые навыки**

14. **Рыбалка**: после последнего `if … else` стоит `else if ($b)` (`plugin/i.fishman.dat:50-64`). Блок «поймал» выполняется,
    только когда ничего не поймано (тогда `$b=0` и выводится «не удалось»). Итог: при улове предмет выдаётся, но **нет
    сообщения «поймал», `st[4]` и опыта**. Первая строка (`:18`) не входит в цепочку `else` и выдала бы сразу два предмета, но
    её порог `S*0,2 < 1` недостижим, так что «часть амулета» не ловится. Поломка удочки 4%, а не 5%, как в комментарии.
15. Кража: метка `vk` берётся из запроса, поэтому шаг подглядывания можно пропустить, подставив `vk` самому
    (`f_useskill.dat:67`). Опыт за кражу дают только в охраняемой зоне (`:84`). Крадётся вся стопка сразу.
16. Приручение не проверяет, есть ли у животного хозяин: можно переманить чужого питомца (`f_useskill.dat:15-29`).
17. Слезая с лошади, игрок превращает купленную (бессрочную) лошадь во временную на 1 час (`f_useitem.dat:16`), так же после `m.kon`.
    `m.kon` переносит кличку через ключ `name_x`, а остальной код через `name` (`plugin/m.kon.dat:29`).
18. Копчение: при провале выдаётся пустая бутылка (`plugin/i.set.koptilka.dat:39`), код скопирован со ступки.
19. Ступки трав дают эликсир (great) из 1 травы с шансом `S*20−5`, а ступка алхимика — из 3 трав с шансом `S*20−20`.
    `i.set.stupka.m` не даёт опыта.
20. Извлечение самоцвета уничтожает предмет при любом исходе. Шанс зависит от количества камней, а не от того, какой извлекается.

21. `plugin/i.c.dat` недостижим, и в нём не хватает `else`: «навык равен 0» выводился бы всегда (`:23`).
22. Голем может появиться в `x1092x474` (банк), но рудной жилы там нет. `c.1.main` в списке мест для самоцветов, но жилы там
    тоже нет (по `content/locations`).
23. Ткачество: все 4 рецепта со сложностью 97 (максимум 3%) и 120-150 нитей за попытку.
24. Ножницы режут на бинты и доспехи `i.a.b.*` (включая металлические).
25. Живая вода: шанс по `rand(1,200)`, вдвое меньше, чем у бинта при той же формуле. Проверка «не призрак» сравнивает с `"0"`,
    пустое значение её не проходит (`plugin/i.ress.dat:10-12`). HP при воскрешении не восстанавливаются (`f_ressurect.dat`).
26. Некромантия считается преступлением в любой ненейтральной зоне (1, 2, 3), а не только в городе (`f_necro.dat:72`).
    Самоцвет `..gt` действительно даёт +10% к шансу (`f_necro.dat:26`), хотя его эффект в данных — пауза атаки (`docs/data-fields.md` §1.4).

**Справка `content/raw/desc` против кода**

30. `skill.mine` «количество добываемой руды», `skill.lumb` «количество … и качество» — всегда ровно 1 единица без качества.
