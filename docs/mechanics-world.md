# Механика мира «Территории Зла»: время, перемещение, NPC, экономика, закон, общение, хранение

Документ описывает, как движок `game/1` ведёт мир **так, как это реализовано в коде**, а не как задумано.
Ссылки `файл:строка` указывают на `game/1/…` (строки считаются после `iconv -f cp1251 -t utf-8`), `portal/…` означает
файлы в `game/` (портал над миром). Имена полей (`char[9]`, `war[15]`, `bank`, `owner`, `o` …) взяты из
`docs/data-fields.md`, квесты описаны в `docs/quests.md`. Бой, смерть, навыки, приручение и развитие персонажа описаны
в отдельных документах о бое и о навыках; здесь на них только ссылки.

Пометка **[не проверено]** означает вывод по коду, который не проверялся запуском. **[?]** означает, что назначение установить не удалось.

## 1. Цикл запроса и время

### 1.1 Как обрабатывается запрос (`g.php`)

Весь мир обслуживает один скрипт `g.php`. Отдельного процесса-«тика» нет: мир меняется только внутри HTTP-запросов игроков.

1. **Переменные запроса.** `extract($_GET/$_POST/$_COOKIE/$_SERVER)` (`g.php:3-6`). Строка запроса очищается от символов вне
   `[ -}А-яЁё]` и разбирается ещё раз (`g.php:17-20`). Если в `QUERY_STRING` есть `/ { } $ " '`, запрос отклоняется с `error`,
   но только когда не заданы `mod`/`adm` и запрос не с `127.0.0.1` (`g.php:70-72`). POST этим фильтром не проверяется.
2. **Константы** `g_*` (`g.php:25-48`, список в §1.4).
3. **Защита от двойного клика.** В `glast.dat` пишется `time().UserAgent.первые 10 символов sid`. Если новое значение совпало с
   предыдущим, то есть тот же браузер и логин повторили запрос в ту же секунду без чужих запросов между ними, выводится
   только ссылка «Обновить» (`g.php:56-60`). Файл общий на сервер и пишется до захвата блокировки.
4. **Глобальная блокировка.** `flock(game.lock, LOCK_EX)` сериализует все запросы сервера. Затем читается `game.dat`
   (`g.php:78-85`). Если `game.dat` нет, мир сбрасывается: `f_online.dat` с `$f_all=1` выгружает всех игроков, и
   подключается `f_blank.dat` (`g.php:84`, см. §7.3). Блокировка снимается в `savegame()` (`g.php:339`).
5. **Плановая остановка / сообщение.** `game['stop']` → `f_stop.dat` (`g.php:90`); `game['msg']` блокирует игру всем, кроме
   запросов с `zx=mda` (`g.php:93`).
6. **Страницы портала** `site=…` → `f_site_<site>.dat` (`g.php:95`), в том числе вход `site=connect2`.
7. **Проверка онлайна раз в 240 с**: если `time() > game['lastai']+240`, выполняется `f_online.dat` (`g.php:97`, §1.3).
8. **Сессия.** `sid` = `логин.пароль.случайная_буква` (`g.php:98-101`). Пароль открытым текстом передаётся в каждой ссылке.
   Жёстко заданный бан по IP, логинам и UA перенаправляет на чужой сайт (`g.php:104`).
9. **Загрузка игрока.** Если файла `online/<login>` нет, выполняется вход (`f_site_connect2.dat`, `g.php:106`). Иначе из
   файла берётся локация, она загружается (`loadloc`, `g.php:615-628`), пароль сверяется с `user[0]` (`g.php:114` →
   `f_npass.dat`). Применяются настройки игрока `o` (`g.php:115`).
10. **Перемещение** `go=` (`g.php:117-138`, §2).
11. **Флаг лидерства** (`g.php:143-144`, §6.6), телепорт в замок `ctele` (`g.php:145`), к супругу `stele` (`g.php:146`).
12. **ИИ.** Загружаются текущая локация и все соседние по выходам. `doai()` выполняется для текущей, затем для каждой соседней
    (`g.php:148-151`, §3). Это единственный «тик» мира.
13. Если игрока в локации нет, `online`-файл удаляется, выводится «Нет данных» (`g.php:153-156`).
14. **Действия** в фиксированном порядке: выход/сохранение `ce` (`g.php:159`), проверка IP (`g.php:160-161`), макросы `cm`
    (`g.php:164-172`), админка `adm` и модерка `mod` (`g.php:174-175`), разговор/взять `speak|cs` (`g.php:177`), `take`,
    `say`, атака `ca` (`g.php:180`), `drop`, клановый блог `dn`/`blogid` (`g.php:182-183`), использование `use` (`g.php:184-199`,
    только если `time() > char[6]`, иначе «Вы должны отдохнуть N сек»), `look`, `msg`, `trade`, списки `cl`/`list`, `map`
    (`g.php:200-211`). Почти каждый обработчик сам завершает запрос через `msg()`.
15. **Главный экран** (`g.php:214-315`): HP/мана, статусы (всадник, призрак, отравлен, титул преступника с оставшимися минутами,
    «с флагом»), «Звуки» (соседние выходы, где есть `u.*`/`n.*`, `g.php:235-243`), список объектов по `g_list` штук
    (`g.php:246-281`), выходы с `accesskey` (`g.php:284-290`), меню.
16. **`msg()`** (`g.php:383-529`) выводит журнал и карточку, **вызывает `savegame()`** (`g.php:414`) и завершает скрипт.
    Главная карточка содержит WML-таймер: через 600 с телефон сам перезапрашивает страницу (`g.php:432`).
17. **`savegame()`** (`g.php:317-342`): для каждой загруженной локации строится `{d, i, t}`. Файл `l_i/<loc>` перезаписывается,
    только если результат отличается от прочитанного (`g.php:327`). Поэтому изменение одного `d` (выходов или названия ворот)
    без изменения `i`/`t` сохраняется, только если код поставил `l_tt[loc]['save']=1` (`f_castle.dat:41,93`,
    `plugin/i.key.tav1.dat:56`, `f_admin.dat:61`). Потом пишется `online/<login>` = `loc\ntime()` (`g.php:332-335`), затем
    атомарно `game.dat` (`g.php:337`).

`msg()` сохраняет мир **всегда**, даже когда выводит ошибку. Любое действие, прерванное посреди работы через `msg()`,
остаётся сохранённым наполовину (см. §8).

### 1.2 Время и «тики»

| Что | Период | Где |
|---|---|---|
| Обработка ИИ, таймеров, распада предметов | на каждом запросе, только для локации игрока и соседних | `g.php:148-151` |
| Регенерация HP/маны | не чаще раза в `g_regen=30` с на объект, прирост пропорционален прошедшему времени | `g.php:532,571-579` |
| Проверка онлайна и выгрузка неактивных | раз в 240 с (по первому запросу после) | `g.php:97`, `f_online.dat:51` |
| Автообновление страницы телефона | 600 с | `g.php:432` |

**Регенерация** (`g.php:571-579`): если с `char[5]` прошло `tm > 30` с и объект ранен, без маны или отравлен:
`hp += round(tm / (30 - 4·regeneration))`, `mana += round(tm / (30 - 4·meditation))` (не выше максимума). Для NPC навыки
считаются нулевыми. Отравленный (`time() < char[17]`) вместо этого теряет `round(tm/10)` HP, но не ниже 1. Призраки
(`u.*` с `char[8]`) не регенерируют. Навыки ограничены 5 (`g_skills_one`), поэтому знаменатель не меньше 10.

**Что происходит без игроков.** Локации, где рядом нет ни одного игрока, заморожены. Таймеры не срабатывают, NPC не ходят,
брошенные предметы не исчезают. При первом визите всё «догоняется» один раз: каждый просроченный таймер срабатывает один
раз (без накопления пропущенных периодов, `g.php:538`), просроченные предметы удаляются, регенерация начисляется за всё
прошедшее время.

### 1.3 Онлайн, выход, выгрузка

* **Файл `online/<login>`**: `loc\nlast_ts[\nretry_ts]`. Пишется при каждом сохранении (`g.php:333-334`). Во время входа
  создаётся метка `.` (1 байт), которая не даёт войти на два сервера сразу (`f_connect.php:30-33`). Метки старше 60 с
  удаляет `f_online.dat:10`.
* **Лимит онлайна** `g_max=100`: вход отклоняется, если в `count.dat` уже `>= 100` (`f_site_connect2.dat:31-34`).
  `count.dat` пересчитывает `f_online.dat:47-49`.
* **Автовыгрузка** (`f_online.dat:5-44`): если `time() > last_ts + g_logout` (600 с), персонаж сохраняется в MySQL
  (`SetData`, без `journal/macrol/trade/inf/lsay1`, с `loc` и `time`, `f_online.dat:27-37`), удаляется из локации (с записью
  «исчез»), и файл `online/` удаляется. Если сохранить не удалось, персонаж остаётся в мире, и попытка повторяется через 240 с
  (`f_online.dat:38-42`). Флаг лидерства при этом бросается (`f_online.dat:17-22`, §6.6).
* **Ручной выход** «[сохранить]» (`ce`, `f_logout.dat`):
  * задумано: нельзя сохраниться раньше 120 с после входа (`f_logout.dat:3`), но условие содержит `$gm!=$gm_id`,
    где обе переменные не определены, поэтому **ограничение никогда не срабатывает**;
  * флаг бросается (`f_logout.dat:18-24`), персонаж пишется в MySQL (`f_logout.dat:27-37`);
  * если в локации **и во всех соседних** нет ни одного `u.*` или `n.*`, персонаж сразу удаляется из мира
    (`f_logout.dat:8-15,42-46`). Иначе он остаётся ещё минимум `g_logout/60 = 10` минут («рядом кто-то есть») и
    выгружается потом через `f_online`. Любой NPC по соседству, даже торговец, считается «кем-то», так что в городе
    персонаж почти всегда остаётся в мире на 10 минут, и его можно убить или обокрасть.
* **Чистка забытых записей игроков** (`g.php:583`): запись `u.*` удаляется из локации **без сохранения**, если
  `char[11]` (последняя активность) старше `5·g_logout = 3000` с и файла `online/` нет.
* **Неверный пароль** (`f_npass.dat`) перезаписывает `online/<login>` строкой `loc\ntime()\n(time()+10)` и выдаёт паузу
  10 с на повтор. Побочный эффект: каждая неудачная попытка обновляет `last_ts`, **и чужой персонаж не выгружается**,
  пока кто-то подбирает к нему пароль (`f_npass.dat:3-6`) [не проверено].
* **Вход** (`f_connect.php` → HTTP-запрос к самому себе `g.php?site=connect2&…&data=<сериализованный персонаж>`,
  `f_connect.php:98`; затем `f_site_connect2.dat`). Если персонаж ещё в мире, берётся его запись из `l_i`
  (`f_site_connect2.dat:10-25`). Иначе данные разбираются, и пароль в `user[0]` **заменяется введённым**
  (`f_site_connect2.dat:53`). Место появления корректируется: `arena` → `x1229x582`, любая `c.N.*` → `c.N.in`,
  комнаты таверны → `x1095x532`, `qv*` → `_begin` (`f_site_connect2.dat:60-69`). Сбрасываются таймеры `char[5,6,11,15,16]`
  (регенерации за время офлайна нет). Срок преступника сдвигается на время офлайна (`f_site_connect2.dat:102-107`).
  Снимается `god` (`:112`). Если клан-сервер сказал, что игрок исключён из клана, из имени убирается `*Клан*` (`:125`).
  Если супруг онлайн и не ссылается на игрока, брак расторгается (`:131-141`).

## 2. Перемещение

### 2.1 Выходы

* Выходы — это пары `label|target` в `d` локации, начиная с индекса 2 (`g.php:284-288`). Номер пары даёт accesskey 1..9.
* `go=<target>`: цель ищется `array_search` по **всему** массиву `d`, включая имя и зону (`g.php:124-127`). Переход
  выполняется, если индекс ненулевой. Совпадение с текстом метки или зоной даёт переход в несуществующую «локацию», который
  `addnpc` молча отбрасывает (`g.php:636`).
* **Ни пауза `char[6]`, ни призрачность, ни бой не мешают идти**: в ветке `go` таких проверок нет. Уйти можно в любой
  момент, в том числе сразу после удара.
* **Скрытность при ходьбе**: с шансом `hiding·8 %` переход не пишется в журналы («ушёл/пришёл», `g.php:132`, `addnpc` `$hide`).
* Входя в зону 1 и выходя из неё, игрок получает «Вы на охраняемой территории» / «Вы покинули охраняемую территорию»
  (`g.php:663-666`).
* Для NPC `addnpc` ведёт след `char[12]` (список пройденных локаций; шаг назад снимает последний элемент, `g.php:653-660`).

### 2.2 Зоны `d[1]`

| Зона | Смысл | Код |
|---|---|---|
| 0 | обычная | — |
| 1 | охраняемая: появляется стража `n.g.*` (§3.4); приказ питомцу напасть на животное считается преступлением | `g.php:558`, `f_speakowner.dat:80` |
| 2 | цитадель тамплиеров: при `Y >= 1099` пираты (`char[14]=p`) попадают в список «преступников» локации | `g.php:552` |
| 3 | форт пиратов: при `Y >= 1099` в список попадают тамплиеры, **обычные преступники в зоне 3 преступниками не считаются** | `g.php:552` |

Зона ещё ограничивает NPC: бродячие (`f_na.dat:11`) и убегающие (`f_run.dat:6`) переходят только в локацию с той же
зоной, а преследователи (`f_goto.dat:8`) тоже, кроме стражи `n.g.*`. Поэтому **от монстров спасает переход в локацию
с другой зоной** (например, из леса в город), а от стражи нет. Распределение зон в `content/locations`: 0 — 1247,
1 — 140, 2 — 10, 3 — 8. Админ может переключить зону 0↔1 командой `adm=guard` (`f_admin.dat:61`).

не выдаёт (`docs/quests.md`), так что двери фактически не используются. Аналогично устроены ключи хранилищ замков `i.key.zh*`.

### 2.4 Верховая езда

* Сесть: `take=n.a.losh.*` на своего (`owner[0]` или `owner[1]`) прирученного коня → `char[12]="1:<hp коня>"`, пауза 3 с,
  конь исчезает из локации, его кличка переходит в `name` (`f_usekon.dat`). Призрак сесть не может.
* Спешиться: `use=i.h` превращает `char[12]` обратно в NPC `n.a.losh.<rand>` с владельцем, на час (`f_useitem.dat:4-21`).

* Боевые эффекты всадника (штрафы/бонусы в `calcparam`, выстрел по всаднику) описаны в документе о бое.

## 3. Жизнь NPC

### 3.1 `doai($i)` — ИИ одной локации (`g.php:530-607`)

`f_doai.dat` — **мёртвая копия** этой функции (нигде не подключается; отличается списком исключённых логинов:
`u.ogir` вместо `u.admin`). Реально работает код в `g.php`. Номера строк: `f_doai.dat:N` = `g.php:N+529`.

Порядок работы для локации `$i`:

1. **Таймеры** (`g.php:537-544`): каждый ключ `t` с `time() > ключ` срабатывает. Строка `n.*` или массив → `f_timernpc.dat`,
   строка `i.*` → `f_timeritem.dat`, иначе `eval()` (в данных таких нет).
2. **Списки** (`g.php:545-557`, ГМ-логины исключены):
   * `$users` — живые игроки, каждый попадает с шансом `100 - hiding·6 %` (скрытых реже выбирают целью);
   * `$crim` — живые игроки-преступники (`char[9]`, кроме зоны 3), пираты в зоне 2 и тамплиеры в зоне 3 (при `Y >= 1099`),
     а также **все** `n.c.*`;
   * `$guard` — есть ли в локации `n.g.*`.
3. **Стража**: в зоне 1, если `$crim` не пуст и стражи нет, появляется один стражник (`g.php:558`, §3.4).
4. **Объекты** (`g.php:561-606`):
   * предметы: `i.flag` удаляется, если `game.floc` не эта локация. В замках `c.*` предметы, кроме `i.s.*`, не
     исчезают. Иначе предмет с `expire_ts` в прошлом удаляется (`g.php:562-568`);
   * у `u.*`/`n.*` начисляется регенерация (§1.2);
   * игроки: истёкший титул преступника снимается (`g.php:581`), активному игроку обновляется `char[11]`, забытая запись
     удаляется (§1.3);
   * NPC, по порядку:
     1. **бегство** (`f_run.dat`): только в локации самого игрока (`$loc==$i`), не в паузе, `HP < max/4`, шанс 50%, не для
        `n.s.`/`n.o.`/`n.z.`. Бежит в случайный выход той же зоны, сбрасывает цель (`g.php:586`);
     2. цель-призрак сбрасывается (`g.php:587`);
     3. `n.a.b.jarpt.1` (жар-птица) уходит в случайный выход, как только в локации есть игрок (`g.php:588`);
     4. стражник `n.g.*` исчезает, когда `time() > char[11]` (`g.php:589`);
     5. питомцы, наёмники, зомби (`owner`) обрабатываются в `f_owner.dat` (документ о навыках/приручении);
     6. **погоня** (`f_goto.dat`): если цели нет в локации, NPC ищет её в соседних и идёт туда (та же зона или стражник).
        Игрок может «скрыться от погони» с шансом `hiding·4 + dex %`, на стражу это не действует (`f_goto.dat:10-13`).
        За призраками не гонятся;
     7. **выбор цели** (`g.php:596-599`): `n.g.`/`n.t.`/`n.p.` берут случайного из `$crim` (включая монстров `n.c.*`!);
        `n.c.*` и NPC с титулом `char[9]` берут случайного игрока из `$users`;
     8. стража замка `n.o.*` в `c.*` (кроме `.in`) атакует чужих, не гостей (`f_no.dat`);
     9. **блуждание** (`f_na.dat`), если цели нет (§3.3);
   * если у не-игрока есть цель, вызывается `attack()` (`g.php:604`). Будет ли удар, решает пауза в `f_attackf.dat`
     (документ о бое).

Так как `doai` выполняется и для соседних локаций, **бои NPC (стража против монстров, монстры против игроков) идут и в
соседних с игроком локациях**.

### 3.2 Появление и респаун

* **Таймер NPC** (`f_timernpc.dat`): строка `npc_id|min:max[:snap]|[wander]`. Для `n.c.`/`n.a.` шаблон ищется без последнего
  сегмента id. Если шаблона нет, таймер молча удаляется (`:7`). В `war[15]` пишется `loc:min:max`, в `char[10]` — параметры
  блуждания. `itemsrnd` разыгрывается: `rand(0,100) <= шанс`, количество `rand(min,max)` (`:15-23`). NPC ставится в
  локацию под своим id и **перезаписывает** одноимённого, если тот там есть (`:26`).
* **Смерть NPC** (`f_kill.dat:69-81`): если есть `war[15]`, в локацию респауна `resp[0]` ставится таймер на
  `rand(min,max)` секунд. Без 4-го элемента это строка «спаун из шаблона» (предметы и `itemsrnd` заново), с 4-м элементом —
  полный снимок NPC с восстановленными HP/маной и предметами из шаблона. NPC без `war[15]` (стража `n.g.`, призванные,
  питомцы) не возвращаются.
* **Таймер предмета** (`f_timeritem.dat`): `id|cmin|cmax|tmin|tmax` ставит в локацию `имя|rand(cmin,cmax)|0` (или удаляет
  при 0) и переводит таймер на `rand(tmin,tmax)`. Количество **заменяет** то, что лежит под этим id, и срок годности
  становится 0 (не исчезает), см. §8.
* Таймеры срабатывают только при обработке локации (§1.2).

### 3.3 Блуждание (`f_na.dat`)

`char[10]` = `max_steps:tmin:tmax:next_ts`, `char[12]` = след.

* Нет `char[10]`, но есть след (NPC, которого увела погоня): каждый тик делает шаг назад, пока след не кончится (`:6`).
* Есть `char[10]`: когда `time() > next_ts`, NPC возвращается на шаг назад, если длина следа `>= max_steps`, иначе
  идёт в случайный выход. Переход разрешён только в локацию той же зоны (возврат по следу разрешён всегда). Следующий ход
  назначается через `rand(tmin,tmax)` (`:7-18`).
* Жар-птица не заходит в занятые локации (`:6,16`).

### 3.4 Городская стража `n.g.*` (`f_addguard.dat`)

Появляется в локации зоны 1, где есть кто-то из `$crim` и нет стражника. Id `n.g.<rand(5,9999)>`, имя
`<случайное> [стража]`, 200 HP, 100 маны; `war`: меткость 100, урон 30-45, пауза 3, броня 100, уклон 30, маг. уклон/парир. 80,
маг. сопротивление 70, алебарда, опыт 15. Живёт 600 с (`char[11]`). Поскольку в `$crim` всегда входят монстры `n.c.*`,
стража появляется и при забредшем в город монстре. Диалог у всех стражников общий: `speak/n.g.guard` (`f_speak.dat:21`).

### 3.5 Товар торговцев

Формат `bank` торговца описан в `docs/data-fields.md` §3.5/§5. Обновление (`f_speakbuy.dat:4-12`, то же в `f_speakbuy2.dat`)
происходит **только когда кто-то открывает список товаров** и `time() > char[11]`. Каждая позиция получает остаток
`rand(min,max)` с вероятностью `шанс %`, иначе 0; остаток **заменяется**, а не добавляется. Следующее обновление назначается
через `период·rand(0.70..1.30)` с, где период — второе поле темы `buy` диалога. Проданное игроками торговцу в `bank` не
попадает (§4.2).

## 4. Экономика

### 4.1 Деньги

* Монеты — обычный предмет `i.money` (цена 1) в `items`. Его можно бросать, передавать, класть в банк, он лежит на трупе.
* Дублоны `i.q.dublon` — квестовый предмет, который **разрешено** бросать и передавать (`f_drop.dat:9`, `f_trade.dat:40`).
  Ими платят у `n.kenius` (`buy2`, цены из `items1/`, `f_speakbuy2*.dat`). Источник — SMS-оплата (см. `docs/quests.md`),
  в текущем окружении недоступен.

### 4.2 Покупка и продажа у NPC

Торговля доступна любому NPC, в диалоге которого есть тема `buy`/`sell` (`f_speak.dat:24-30`). `n.Natan` торгует (в обе
стороны) только с тем, у кого есть `i.q.hagen` или `i.q.ditrih` (`f_speak.dat:26`).

* **Покупка** (`f_speakbuyto.dat`): `цена = round(price · num · buy_mult)`, где `buy_mult` — первое поле темы `buy`; при
  `price <= 1` множитель равен 1 (`:15-18`). Нужна сумма `i.money` в рюкзаке. Сначала списываются деньги, потом предмет
  переходит из `bank` торговца (`:21-22`). Руны всегда стоят 50 (`:4`).
* **Продажа** (`f_speaksellto.dat`): `цена = round(price · num · sell_mult)` (`:25-26`), где второе поле темы `sell` —
  фильтр подстрок id через `:`; без фильтра NPC покупает всё. **Деньги начисляются до изъятия предмета** (`:27-28`).
  Проданный предмет исчезает: у торговца нет ни кошелька, ни склада для скупки.
* Количество `num` не приводится к целому перед расчётом цены, а `additem` берёт `intval` (см. §8, эксплойт с `num=1.99`).
* Округление идёт по всей партии: покупать дешевле поштучно, продавать выгоднее оптом.
* Проверка арбитража по всем парам «продаёт X / покупает Y» в `content/` (множители и фильтры): **прибыльных пар нет**.
  Сходятся в ноль только цветы `i.bc.*` у `n.Katrina`/`n.m.Gred` (1.0/1.0) и предметы ценой 1.

### 4.4 Банк (`f_speaktobank*.dat`, `f_speakfrombank*.dat`)

* Одна ячейка на игрока (`bank`, item list), общая для всех банкиров мира.
* Положить (`tobankto`): не больше 70 000 монет в банке, проверяется только при вкладе `i.money` (`f_speaktobankto.dat:14`).
  Если `bank` длиннее 800 символов и такого предмета там ещё нет, выводится «Нет места» (`f_additem.dat:25`).
  Комиссия за вклад: у `n.t.bankir` 20 монет, у `n.p.bankir` 200 (`:15-16`). Комиссия списывается **до** проверки места.
* Забрать (`frombankto`) без ограничений. Если рюкзак полон, предмет падает под ноги (§4.6).
* Порядок в ячейке меняется командами `up`/`down` (`f_speakfrombankm.dat`).
* Фракционная проверка тамплиеров/пиратов стоит только в списках (`f_speaktobank.dat:4-5`, `f_speakfrombank.dat:4-5`),
  а не в самих операциях `…to`. Прямой URL `id=tobank&to=…` или `id=frombank&to=…` работает у чужого фракционного
  банкира [не проверено].
* `f_speaktobank.dat:2-3` вычисляет «время суток» через `f_time.dat` (часы·11 в `mktime`), но результат не используется:
  ограничения по часам закомментированы.

### 4.5 Обмен между игроками (`f_trade.dat`)

* Начать: `trade=u.X` (оба живые, в одной локации). У каждого создаётся `trade = {to, i, ito, a}` (`:11`), второй получает
  запись в журнал. Если второй уже начал обмен с первым, списки связываются (`:15`).
* `trade=add&id=…&num=…`: проверка наличия (`additem … count`). Квестовые `i.q.*` нельзя, кроме `i.q.dublon` и `i.q.pjpt`
  (`:40`). `num` приводится к целому (`:46`). Любое изменение списков сбрасывает согласие обеих сторон (`:52-53`, `:62-63`).
* `trade=agry`: ставит `a=1`. Если строки списков у сторон совпадают крест-накрест и оба согласны, наличие ещё раз
  проверяется по рюкзакам (`:88-89`), затем вещи передаются по одной через `additem` (`:91-92`).
* Передача **не атомарна**: `additem` с `$msg=1` может прервать запрос посреди цикла (например, второе перо жар-птицы
  `i.q.pjpt` или третий стеклянный меч, `f_additem.dat:23-24`), и уже переданное сохранится (§8).
* Можно передать и с полным рюкзаком: лишнее падает получателю под ноги.
* Чат внутри окна обмена отправляет `say` (`:123-128`).

### 4.6 Бросить, поднять, распад, лимиты

* **Лимит рюкзака и банка — 800 символов строки** (`id:count|…`), а не количество или вес. **Веса в игре нет** (в коде
  проверок веса не найдено). Если `items` длиннее 800 и такого id там нет, полученный предмет падает под ноги
  («Не хватает места…», `f_additem.dat:108-112`). Проверка идёт до добавления, так что строка может превысить 800 на одну
  запись. Отдельный предел — 5000 байт сериализованного персонажа в MySQL (`datafunc.php:153-154`); если его превысить,
  сохранение не проходит («Слишком длинная строка»).
* **Бросить** (`f_drop.dat`): нельзя призраку, нельзя квестовые `i.q.*`, кроме `i.q.dublon`, `i.q.pjpt` (и логина `u.ogir`).
  Брошенное лежит `имя|кол-во|time()+g_destroy` (600 с). Добавление к той же кучке продлевает срок всей кучке
  (`f_additem.dat:130-138`). Броски ГМ-логинов пишутся в `z_modlog.dat` (`f_drop.dat:25-28`).
* **Поднять** (`f_take.dat`): нельзя `i.s.*`, кроме трупов, `i.s.res` (воскрешение призрака) и порталов (`:23`).
  Нельзя призраку и в стойке «глухая оборона» `p.d.o` (`:24-26`). Количество запрашивается формой.
* **Трупы** `i.s.d.*` (`f_takediedid.dat`, `f_takediednoid.dat`): исчезают через `g_destroy`. Квестовые предметы с чужого
  трупа игрока взять нельзя (`f_takediedid.dat:5`). Взятие даёт паузу 2 с (`:17`). Мародёрство см. §5.1.
* **Распад** (`g.php:562-567`): предмет с `expire_ts` в прошлом удаляется, **только когда локацию обрабатывает `doai`**.
  Предметы, выложенные таймерами, `i.flag` и объекты `i.s.*` имеют срок 0 и не исчезают. В замках `c.*` не исчезает ничего,
  кроме `i.s.*` с истёкшим сроком (порталов).

### 4.7 Источники и стоки денег

**Источники:** монеты в `items`/`itemsrnd` у 68 шаблонов NPC (добыча с трупа); продажа предметов торговцам (сырьё
`i.log`, `i.ruda`, шкуры `i.h.*`, найденное оружие и броня); награды в 35 диалогах (от 20 до 50 000 монет; 50 000 даёт

ГМ-команды `adm=mnn` и `mod=add`.

**Стоки:** покупки у торговцев; обучение навыкам (`f_speakskillup.dat:131`, `…m.dat:10`, `…p.dat:8`); создание клана 50 000
и камень гильдии 500 (`n.guildmaster`); комиссия фракционных банков 20/200; стража замка 20-70, продление контракта

Ограничитель накопления — только лимит 70 000 при вкладе в банк. В рюкзаке денег может быть сколько угодно.

## 5. Преступления и закон

### 5.1 Статус преступника

`docrim($loc,$login,$title,$crim)` (`f_docrim.dat`) ставит `char[9]=титул`, `char[10]=time()+g_crim-$crim`. Действует только

продлевает, а **перезапускает** срок от текущего момента.

| `вор` | замечен при краже или подглядывании в рюкзак | 1800-600 = **1200 с** | `f_useskill.dat:65,85,87` |

**Кто «невиновный»** (`f_attackf.dat:54-59`): цель не преступник, не `n.c.*`, не `n.w.Veelzevul`, не `n.whitewolf`, не держатель

**Труп «свободный»** (`free_loot=1`): труп преступника или `n.c.*`, животного, либо труп в замке вне `.in` (`f_kill.dat:17`).

**Последствия**:
* в зоне 1 появляется стража (§3.4). Стражники, `n.t.*` и `n.p.*` атакуют преступников в любой зоне;
* атака на преступника и мародёрство с его трупа не преступны;
* на главном экране виден титул и оставшиеся минуты (`g.php:228`), при осмотре тоже;
* `war[15]` «кто убил / кого убил» и награда за голову у `n.officer` (`f_kill.dat:56-59,100-102`, `docs/quests.md` §47).

### 5.2 Фракции: тамплиеры и пираты

* Вступление и выход идут через диалоги банкиров и Лаймы, пишут `char[14] = t | p | ''` (`docs/quests.md` §27-28).
* Фракция видна у игрока только на `Y` от 1099 до 1370 (`g.php:265-266`).
* Зона 2 (цитадель): пираты попадают в `$crim`, их атакуют `n.t.*`. Зона 3 (форт): тамплиеры попадают в `$crim`, их атакуют

  в зоне 1).
* Фракционный банк (§4.4) и торговля у `n.t.bankir`.

## 6. Общение и социальное

### 6.1 Речь `say` (`f_say.dat`)

* Слышат только игроки в той же локации (`addjournal(…,"all")`, `:70`). Длина до 250 символов (`:63`).
* Фильтр: вырезаются кавычки, `\`, `$`, `&`, `|`, `<`, `>`, домены `.ru/.org/.net/.com/.ua`. Мат заменяется на `[бип]`
  регулярками (`:15-34`). Регулярка `\w*(х|x)(у|y)\w*` глушит любое слово с «ху»/«xy» [проверить в cp1251-локали].
* Бан чата `ban` (ставит ГМ на 24 ч) → «Бан!» (`:64`). Повтор той же фразы (crc32) запрещён (`:65`).
* Отравленный говорит с подменой букв (`:36-62`, та же подмена накладывается на весь экран, `g.php:472-497`).
* **Призрак**: с шансом `spiritism·10 %` его слышат все, иначе каждый слушатель с шансом `spiritism_слушателя·20 %`, а
  остальные видят «OOoo…» (`:69-83`).

### 6.2 Личные сообщения и контакты (`f_msg.dat`)

* Контакты `msg` — список логинов до 500 символов. Добавить можно только того, кто рядом (`:71-81`).
* Написать (`msg=write`) можно только онлайн-адресату, который **сам добавил отправителя в контакты** (`strpos` по логину,
  поэтому `u.bob` проходит и у `u.bobby`, `:173`). `mall` рассылает всем взаимным контактам онлайн (`:166`). Текст до 140
  символов дописывается во входящие `msgt` адресата, от которых хранятся последние 500 символов (`:175`).
* **Все личные сообщения пишутся в `x_konti.txt`** (новые сверху, файл до ~195 КБ, `:177-197`).
* Сообщение клану (`msg=klan`) уходит всем онлайн-членам клана, без проверки контактов (`:102-143`).
* `msgt` удаляется при ручном сохранении (`f_logout.dat:31`), но **не** при автовыгрузке (`f_online.dat:31-34`) и
  попадает в MySQL.
* В меню есть ссылка на внешний форум с логином и паролем в URL (`:6`).

### 6.3 Кланы

* Хранятся на портале: `game/clans/<имя>` (сериализованный массив: `g` — сеньор/глава `{login: пароль}`, `s` — сенешали,
  `v` — вассалы, `m` — неофиты, `w`/`wg` — приглашённые, `i` — описание). Член клана отмечается в имени: `Имя *Клан*`.
* Создание: `n.guildmaster` Мирандер (`x1086x501`), тема `newnow2`: имя до 20 символов `\w`, **50 000 монет**; даёт
  `i.guildstone`. В файл клана записывается **пароль главы** (`"g"=>array($login=>$p)`). Камень гильдии для замены стоит 500.
* Управление — `plugin/i.guildstone.dat`: глава или сенешаль приглашает (`w`), приглашённый использует камень на главу;
  глава исключает (`del`) и передаёт главенство (`wg`). Исключённый теряет `*Клан*` при следующем входе
  (`f_site_connect2.dat:125`, проверка `portal/f_common.php?inclan=`).
* Эффекты в движке: атака, убийство и мародёрство внутри клана не преступны (`f_attackf.dat:59`, `f_kill.dat:28`,
  `f_additem.dat:86`); клановые сообщения; клановый блог `dn`/`blogid` (`d.dat`, `c.dat`, отдельная MySQL-база с жёстко
  прописанными реквизитами, в текущем окружении не работает); замки.
* Список кланов: `site=clans` (`f_site_clans.dat`).
* **Замки** (подробно в `docs/quests.md` §52). Состояние хранится в имени ворот `c.N.gate`: `…*Клан*(вывеска):u.гость:…{запертодо}#открытодо#[стук]`.
  Захват (`f_castle.dat:46-94`): игрок в клане входит в `.gate` чужого замка, где в `main/gate/tron/sklad` нет ни стражи
  `n.o.*`, ни живых членов клана-владельца или гостей → замок переходит его клану, ворота открыты 2 ч (`:89-90`), онлайн-члены
  прежнего клана извещаются. При входе в чужой замок владельцы получают ссылку «На ваш замок напали!» для телепорта `ctele`
  (`:64-70`). Ворота запираются через стражу (`f_speako.dat`) и открываются хозяевами (`f_castlein.dat:43-56`). Стучать
  можно раз в 3 минуты (`f_castlein.dat:11-31`). Призрак-чужак выталкивается в `.in` (`f_castle.dat:14`). Стража `n.o.*`
  нанимается по контракту (`owner[3]`, продление 50/60/70/100 в день, `f_speako.dat:84-93`) и атакует чужаков (`f_no.dat`).
  Хранилища: `c.N.sklad`, комнаты с ключами `i.key.zh*`.

### 6.4 Брак (кратко)

Заключается у `n.Lajma` (`docs/quests.md` §27), хранится в `char[13] = u.супруг:ts`. Движок учитывает брак так: атака,
убийство и мародёрство супруга не преступны (`f_attackf.dat:58`, `f_kill.dat:28`, `f_additem.dat:86`,
`f_takediednoid.dat:10`); при ранении супруга второму приходит ссылка-телепорт на 5 минут (`f_attackf.dat:115-130`,
`f_stele.dat`); при входе брак расторгается, если супруг онлайн и не ссылается на игрока (`f_site_connect2.dat:131-141`).

### 6.5 Макросы

До 8 слотов `macro` (`var|val|var2|val2|label`, всего до 300 символов, `f_macro.dat:5-18`), кнопки в меню (`g.php:445-446`).
Слот может ссылаться на последнее действие `macrol` (`last`). Исполняются через `eval('$var="val";')` (`g.php:164-171`).
Имена переменных и `to` фильтруются `f_blok.dat`, **значения `objz`/`toz` не фильтруются** (§8).

### 6.6 Флаг лидерства

* Хранится в `game.dat`: `floc` (локация), `fid` (держатель или `''`), `fchar` (имя для карты). Лежащий флаг —
  предмет `i.flag = флаг лидерства|1|0` (`g.php:144`).
* Поднять `take=i.flag` может живой игрок (`f_take.dat:7-15`). У держателя `floc` обновляется на каждом запросе
  (`g.php:143`, `g.php:336`).
* Бонусы, пока держатель в `floc`: +10 к макс. HP (`f_calcparam.dat:11`), +20 к шансу заклинаний (`f_usemagic.dat:26`,
  `f_lookmagic.dat:18`), +10 к меткости приёмов (`f_usepriem.dat:24`, для NPC `f_mobpriem.dat:22`). Цена: держатель
  **считается законной целью** (`f_attackf.dat:56`).
* Флаг теряется: при смерти (падает на месте, `f_kill.dat:38`); при `drop=f` (`f_drop.dat:5`); при выходе и
  автовыгрузке (`f_logout.dat:18-24`, `f_online.dat:17-22`). Из комнат таверны флаг переносится в `x1095x532`, из хранилищ
  замков — в `c.N.in`. Ключи таверны и хранилищ выбрасывают флаг из запираемой комнаты (`plugin/i.key.*.dat:32`).

### 7.2 Что переживает перезапуск

В памяти между запросами ничего не хранится, и каждый запрос заканчивается сохранением на диск. Поэтому перезапуск
веб-сервера ничего не теряет, кроме прерванного запроса (запись `game.dat` атомарная, `g.php:76-77`). Игроки, которые
были «онлайн», остаются в `l_i` и `online/` и после перезапуска выгружаются обычным порядком через `f_online`. Если
выгрузка в MySQL невозможна (нет БД), персонаж остаётся в мире в `l_i`.

Персонаж, выгруженный в MySQL, вне мира не существует: его нельзя убить или обокрасть, его предметы на нём. Всё, что он
оставил в мире (брошенное, труп), живёт по правилам распада.

### 7.3 Сброс мира (`F_blank.dat`)

Вызывается `adm=blank` (`f_admin.dat:48`) и при отсутствии `game.dat` (`g.php:84`, **но там подключается `f_blank.dat` в
нижнем регистре**, и на Linux это падает). Сначала всех выгружают (`f_online` с `$f_all=1`). Затем у всех локаций, кроме
`c.*` (замки), очищаются объекты (NPC, предметы, **игроки**) и таймеры, и ставятся стартовые предметы и таймеры из
`F_blank.dat`. Замки, кланы, MySQL и `game/*.dat` сброс не трогает.

## 8. Странности и ошибки

Отмечено, что является **эксплойтом** (выгодно игроку или злоумышленнику), а что просто ошибкой.

**Безопасность и полный доступ**

1. **Бэкдор `zx=mda`.** `f_admin.dat:3` пускает в админку любого, кто передал `zx=mda` (`$zero='mda'`, `g.php:28,173`).
   Это даёт деньги, предметы, телепорт, бога, сброс мира и список онлайн с паролями. `zx=mda` ещё снимает блокировку
   `game['msg']` (`g.php:93`), лимит онлайна (`f_site_connect2.dat:34`) и проверку оплаты (`f_connect.php:74`). **Эксплойт.**
2. **Вход с `zx=mda`** подключает `f_gmlogin.dat`: параметры запроса `items`, `bank`, `skills`, `magic`, `add` записываются
   прямо в персонажа (`f_gmlogin.dat:2-3`). Нужен только свой пароль. **Эксплойт.**
3. **Макросы → `eval`.** Значения макроса (`objz`, `toz`) не фильтруются (`f_blok.dat` чистит только `obj`, `to`, `name`) и
   исполняются как `eval('$'.$var.'="'.$val.'";')` (`g.php:169-171`). Если передать их POST-ом (фильтр `g.php:71`
   проверяет только `QUERY_STRING`), кавычка в значении даёт исполнение PHP. Имя переменной `obj` может быть,
   например, `login`, и тогда после проверки пароля подменяется действующий логин. **Эксплойт [не проверено].**
4. **`portal/f_common.php` без авторизации**: `sclan` перезаписывает любой клан, `dclan` удаляет файл
   `clans/<параметр>` (с `../` — **любой файл**, `:44`), `swanted` перезаписывает список наград, `payed`/`reg2` накручивают
   счётчики. **Эксплойт.**
5. **Подделка данных входа.** `f_connect.php` передаёт персонажа в `g.php?site=connect2&data=…` параметром URL
   (`f_connect.php:98`). `f_site_connect2.dat` принимает `data` от клиента, если есть файл `online/<login>` (метка `.`
   существует, пока идёт вход, до 60 с), и заменяет в данных пароль на введённый (`:28,47-53`). Злоумышленник, который
   успевает прислать свой `data` для своего логина, входит с произвольным персонажем. **Эксплойт [не проверено].**
6. **ГМ-права по логину.** Админка и модерка проверяют только логин (`u.admin`, `u.qv`, `u.qw`, `u.kv`, `u.scream`, `u.sn0k`,
   `u.wildspb`, `u.ps_one`). В новой пустой базе эти логины может зарегистрировать кто угодно (`ValidNN` их не запрещает,
   `datafunc.php:49-52`). **Важно при перезапуске.**
7. Пароли хранятся и передаются открытым текстом: в `sid` каждой ссылки, в `user[0]` в `l_i`, в MySQL, в файле клана
   (пароль главы), в админском списке онлайн, в ссылке на форум (`f_msg.dat:6`), в ссылке «супруг ранен» (журнал
   `f_attackf.dat:126`). В `d.dat`/`c.dat` зашиты реквизиты сторонней MySQL.
8. Личные сообщения логируются в `x_konti.txt` (`f_msg.dat:177-197`).

**Экономика**

9. **Дробное количество при продаже.** В `f_speaksellto.dat` цена считается от `num` как от числа (`legacy_num`), а
   `additem` изымает `intval(num)` (`f_additem.dat:5`). `num=1.99` при двух предметах в рюкзаке даёт 1.99 цены за один
   предмет. Фильтр `g.php:19` точку пропускает, ограничение `format="*N"` действует только в браузере. У `n.Julien`
   (покупка 1.0, продажа 0.8) это даёт прибыль на свитках: купить за p, продать за 1.59p; цикл ограничен только запасом
   торговца. Торговцы без фильтра (`n.Goston`, `n.Ruf`, `n.Sloven`, `n.Sten`, `n.p.Tina`) принимают даже `to=i.money`
   (цена 1, множитель принудительно 1): «продажа» `M-0.01` монет из `M` даёт +1 монету за запрос. **Эксплойт
   [не проверено запуском].** Для покупки то же самое только вредит покупателю.
10. При продаже деньги начисляются до изъятия предмета (`f_speaksellto.dat:27-28`). Сейчас это не эксплуатируется, потому
    что количество проверено выше.
11. Неатомарный обмен и прерывания `msg()` посреди действий: `msg()` всегда сохраняет мир (`g.php:414`), поэтому
    оборванный обмен (`f_trade.dat:91-92`), покупка с полным банком после комиссии (`f_speaktobankto.dat:15-17`) и т.п.
    остаются сделанными наполовину.
12. Фракционные банки без проверки фракции в операциях `tobankto`/`frombankto` (§4.4) [не проверено]. `n.beginner` работает
    как банкир из-за темы диалога `bank` (§4.3) [не проверено].
13. `n.gregor` объявлен торговцем, но товара у него нет (§4.3). У `n.tamozh` в `bank` лежит пустой id `90:10:10=:5000`, а
    весь ассортимент, включая 10 000 хлопушек и петард, стоит по 1 монете.
14. Регулярки поиска количества без экранирования (`/.*<id>:(\d+).*/`) путают id-префиксы (`docs/data-fields.md` §5);
    `strpos($login.":")` в аренде таверны и `strpos($login)` в контактах совпадают по префиксу логина.
15. Таймеры предметов **заменяют** количество под своим id и ставят срок 0 (`f_timeritem.dat:5`). Предметы, брошенные
    игроком в такой точке (например, камни `i.w.r.stone` в `x1476x277`), перезаписываются, а выложенные таймером никогда
    не исчезают.

**Время, онлайн, сохранение**

16. Запрет выхода в первые 120 с не работает: условие `$gm!=$gm_id` на неопределённых переменных всегда ложно
    (`f_logout.dat:3`).
17. `f_logout.dat:18-24` присваивает `$game["floc"]=$locl` (опечатка вместо `$loc1`). После ручного выхода с флагом `floc`
    становится пустым, и на следующем запросе любого игрока флаг появляется **у него под ногами** (`g.php:144`).
18. После входа из хранилищ замков 3-5 (`z.*z3..5`, `z.N.sklad/hran`) персонаж появляется в `c.2.in`, а не в своём замке
    (`f_site_connect2.dat:65-67`, копипаста).
19. Цикл «защиты» навыков при входе ничего не делает (`f_site_connect2.dat:72-78`: `implode` того же массива).
20. Неверные пароли продлевают чужой онлайн (§1.3), ручной выход в городе почти всегда оставляет персонажа в мире на 10
    минут из-за мирных NPC рядом (§1.3), а WML-таймер на 600 с при открытом телефоне держит игрока онлайн бесконечно
    (`g.php:432` против `g_logout=600`).
21. Если MySQL недоступна, `SetData` возвращает ошибку, и `f_online` бесконечно держит всех «выгружаемых» в мире.
    Персонаж длиннее 5000 байт не сохраняется никогда (`datafunc.php:153-154`), а при ручном выходе игрок видит только
    ошибку.
22. `SetData` сохраняет «без пароля» (`skippass=1`), но проверяет паузу `PassDelay` (`datafunc.php:119-120`), которая нигде
    не задана (равна 0), поэтому пауза не действует.
23. `f_online.dat` (исходно в UTF-8, а не в cp1251) пишет имя флага `флаг лидерства` в UTF-8, в cp1251-мире оно
    отображается кракозябрами [не проверено].
24. `g.php:84` подключает `f_blank.dat`, а на диске лежит `F_blank.dat`.
25. `F_blank.dat` содержит повторяющиеся ключи таймеров: в `x903x272` из четырёх предметов остаётся один (ветчина), в
    `x1446x60` из двух один (рубин), `x2316x272` задан дважды. Есть опечатка `n.c.n.c.mumyl.*` (шаблона нет, таймер
    удаляется молча) и ссылка на несуществующий `i.f.moroz`. Таймеры `i.s.nakov|1|0` и `i.s.res|1|0` в замках без периода
    срабатывали бы каждую секунду, а количество `rand(1,0)` то ставило бы, то убирало объект. В текущем `content/` этих
    таймеров в замках нет.
